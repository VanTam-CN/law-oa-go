# 客户API 422错误修复成功报告

## 📋 问题概述

**问题描述**: 用户报告"新建案件里，委托人只剩下 2 个了，没有全部客户的信息"
**报告时间**: 2025-10-14 17:12
**问题等级**: 中 (功能缺陷)
**影响范围**: 新建案件功能的委托人选择

## 🔍 问题诊断

### 1. 问题现象
- 新建案件的委托人下拉选项只显示2个客户，而不是所有可用客户
- 前端控制台显示客户API调用返回422状态码
- 错误发生在CreateCaseWizard组件的客户数据获取过程中

### 2. 根本原因分析
通过系统性诊断，发现问题的根本原因在于**API参数验证错误**：

#### A. PageSize参数超过后端验证限制
- **前端发送**: `pageSize: 1000`
- **后端验证规则**: `max=100`
- **问题所在**: `ClientListRequest.PageSize` 字段有 `binding:"omitempty,min=1,max=100"` 验证标签

#### B. 参数格式不匹配
- **前端服务**: 将 `pageSize` 映射为 `page_size`
- **后端期望**: `page_size` 参数最大值为100
- **验证失败**: 1000 > 100，导致422 Unprocessable Entity错误

## 🛠️ 修复方案

### 1. 核心修复策略
**限制前端请求的pageSize最大值，确保符合后端验证规则**

### 2. 具体修复内容

#### A. 修复前端客户服务参数限制
**位置**: `frontend/src/services/client.ts:51`

**修复前**:
```typescript
page_size: params.pageSize || 10,
```

**修复后**:
```typescript
page_size: Math.min(params.pageSize || 10, 100), // 🔧 修复：限制最大值为100，符合后端验证规则
```

#### B. 保持现有的参数映射逻辑
**确认**: 前端到后端的参数映射逻辑正确
- `pageNum` → `page`
- `pageSize` → `page_size`
- `name` → `search`
