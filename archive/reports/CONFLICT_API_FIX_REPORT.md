### 2. 根本原因分析
通过系统性诊断，发现问题的根本原因在于**数据类型转换错误**：

#### A. UserID字段类型不匹配
- **前端发送**: 字符串类型 `"userId": "1"`
- **后端模型**: uint类型 `UserID uint`
- **问题所在**: conflict_handler.go:110 行存在未实现的TODO注释
  ```go
  UserID: 0, // TODO: 转换字符串到uint
  ```

#### B. SearchDepth枚举值错误
- **测试脚本发送**: 小写 `"deep"`
- **模型验证要求**: 大写枚举值 `BASIC|STANDARD|DEEP`
- **验证规则**: `validate:"oneof=BASIC STANDARD DEEP"`

## 🛠️ 修复方案

### 1. 核心修复策略
**实现字符串到uint的安全转换，移除TODO占位符**

### 2. 具体修复内容

#### A. 修复UserID类型转换
**位置**: `internal/handlers/conflict_handler.go:99-120`

