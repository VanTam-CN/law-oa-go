# 律所非 IT 多角色冲突检查演练记录

- 日期：2026-07-15
- 环境：本机 `127.0.0.1:3003`，本机正式 API 与本地数据库
- 方法：Chrome 页面自动化、屏幕坐标操作与桌面 Computer Use 交叉检查
- 数据边界：仅使用已有演示账户和完全虚构的案件、客户与复核理由；未读取或提交真实客户资料。
- 演练角色：承办律师、律师助理、核查管理角色（管理员）。当前系统没有可验收的独立“冲突核查人”角色，故管理员仅用于验证现有管理端能力，不等同于 P0 Spec 所要求的角色设计。

## 演练数据与路径

虚构案件：`验收演练-远岚科技股权回购争议`。

1. 承办律师新建案件，选择虚构客户“青海云岭建设集团有限公司”，填入对方“上海示例科技有限公司”，指定负责律师。
2. 运行冲突检测，系统创建接案草稿并命中“规范化名称完全一致”。
3. 承办律师从“进入本案冲突复核”进入带案件上下文的检测清单。
4. 管理角色打开同一条记录，填写“确认冲突”及虚构复核依据，提交人工复核。
5. 系统回写为“已暂停接案”，继续阻断立案；打开豁免申请后，以空理由提交，系统提示必须填写豁免理由，随后取消申请。
6. 律师助理登录后，验证工作台、立案入口、直接访问冲突页的权限表现。

## 工程师问题单

### ISSUE-01 P0：登录页预填特权账户凭据

**复现**：任一用户退出登录后回到 `/login`，账号和密码输入框自动填入特权账户凭据。

**影响**：浏览器截图、共享屏幕、公共终端或误部署的演示环境都会暴露可用凭据；这是发布前的直接安全阻塞项。

**代码证据**：[SimpleLogin.tsx](/Users/mac/Desktop/FT/law-oa-go/frontend/src/pages/auth/SimpleLogin.tsx:31) 和 [SimpleLogin.tsx](/Users/mac/Desktop/FT/law-oa-go/frontend/src/pages/auth/SimpleLogin.tsx:43) 对账号和密码设置了 `defaultValue`。

**修复要求**：移除生产构建中的全部默认账号、默认密码和演示登录捷径；测试账户仅存在于 E2E fixture 或显式本地开发开关中。增加 E2E 断言：登录页两个输入框均为空。

### ISSUE-02 P0：受限历史案件信息向普通律师过度披露

**复现**：承办律师在严重命中记录点击“查看详情”。

**实际结果**：页面展示所有命中案件的编号、标题、状态、当事人关系和证据链，并明确写出历史客户和承办律师关系。

**影响**：与 P0 Spec 的“受限命中仅返回数量与联系核查岗；承办律师不应见受隔离历史案情、团队、工作底稿”冲突。普通承办律师可据此推断不属于自己的历史客户和案件信息。

**修复要求**：按角色和隔离墙做字段级投影。普通律师仅可见“存在 N 条受限命中、冲突类别、下一步联系对象”；冲突核查人、经授权的管理合伙人才能查看命中案件明细。E2E 需以无关律师账号验证标题、编号、状态、证据链均不可见。

### ISSUE-03 P0：助手工作台泄露冲突数据且给出无效入口

**复现**：律师助理登录后进入工作台。

**实际结果**：尽管侧栏不显示“利益冲突检查”，工作台仍显示“利益冲突待复核”数量、案件标题、客户名称和“查看全部冲突任务”按钮；点击该按钮才得到“无权访问”。

**影响**：先泄露再拒绝访问，既违反最小披露，也让非 IT 助理误以为系统故障。该问题同时证明工作台聚合接口没有应用与冲突页一致的授权投影。

**修复要求**：在服务端聚合层按权限移除冲突计数、卡片、搜索命中和近期活动；无 `conflict:check` 的角色不渲染该入口。加入“助理工作台不含案件标题、客户名、数量、跳转按钮”的 API 和浏览器测试。

### ISSUE-04 P0：助理可进入完整立案表单并启用最终检测动作

**复现**：律师助理点击“新建立案”。

**实际结果**：可进入 `/case/create`，可编辑客户、对方、身份相关字段，且“保存草稿”和“保存并进行利益冲突检查”均为可用状态。

**影响**：这与已确认的试用规则相反：助理只能录入、整理、催办；不得录入/修改身份标识、运行最终检索或下结论。即使后端提交时拒绝，前端也会把错误能力暴露给用户；本轮未提交助理表单，故仍须补做服务端拒绝测试。

**修复要求**：建立 `assistant_draft` 状态与受限字段白名单；身份标识字段、最终冲突检测、提交审批必须由律师账户执行并在 API 层强制校验。新增助理正向草稿、助理越权提交返回 403、律师接手确认三组 E2E。

### ISSUE-05 P0：检索范围仍是“五年 + 文本/名称”，不足以支持“确认冲突”

**复现**：打开本次严重命中的检测详情。

**实际结果**：页面明确显示“标准检索 · 5年”，检索范围仅说明本所授权案件库中的客户名称、案件标题摘要和已登记关系；规范化主体中“身份标识数量”为 0、“别名数量”为 0。

**影响**：与 P0 Spec 的全量回溯、权威来源边界、统一社会信用代码/身份证件号、曾用名/别名/关联方检索不一致。没有强身份标识时，名称规范化只能形成待确认候选，不能在界面上以“确认冲突”作为自动事实。

**修复要求**：先落实 PD-01、PD-05；默认全量回溯，任何配置窗口须显著标识超窗缺口；为主体、关系、来源库和扫描快照补齐结构化字段。自动结论只能是“未命中/受限命中/待人工确认”；人工结论可以推翻，但必须留理由和证据引用。

### ISSUE-06 P1：候选命中同时显示“是否冲突：否”与“待人工复核”

**复现**：在冲突清单筛选中风险，打开“名称候选，待人工核实”记录。

**实际结果**：详情写“是否冲突：否”，同时又要求独立人工复核并提示不得继续提交立案。

**影响**：非 IT 律师会把“否”理解为可以接案，和后续阻断语义冲突。

**修复要求**：三态改为“已确认冲突 / 未发现可识别冲突（范围说明） / 待人工确认”；候选记录不可出现“否”。

### ISSUE-07 P1：承办律师的复核交接动作不清晰

**复现**：严重命中后，承办律师进入“本案冲突复核”。

**实际结果**：页面提示“请发起冲突审批”，但承办律师只看到“进入本案冲突复核/查看本案检测结果”，没有明确的“提交至某核查人”动作、接收人、时限或待办确认。

**影响**：承办律师无法判断自己是否已把案件交给独立复核人，容易停在详情页反复查看。

**修复要求**：提供单一主按钮“提交给冲突核查人”，展示核查人、替代人、SLA 和状态流转；提交后创建可追溯待办。该按钮不得由申请律师自行完成最终结论。

### ISSUE-08 P1：复核结果页缺少可读的审计链

**复现**：管理角色提交“确认冲突”后重新打开详情。

**实际结果**：可见状态已回写和更新时间，但详情中没有向用户呈现复核人、复核理由、复核时间、依据引用和前后状态。

**影响**：律师、主任和合规人员不能凭页面回答“谁基于什么确认了冲突”。

**修复要求**：在“人工复核记录”展示不可篡改的追加记录；最少包含操作者角色与显示名、时间、结论、理由、证据引用、前后状态和回避信息。

### ISSUE-09 P1：豁免申请缺少书面同意与授权材料门槛

**复现**：管理角色在已确认冲突记录点击“申请豁免评估”。

**实际结果**：表单要求文字理由、风险控制和有效期，但无客户书面同意附件、豁免模板、审批权限、回避确认、续期/撤销条件等字段。

**影响**：界面文案说“独立复核”，但无法证明豁免材料齐全；默认有效期也没有对应律所决策依据。

**修复要求**：待 PD-06 生效后，将材料清单、上传/引用、审批矩阵、回避确认、有效期和撤销条件作为服务端必填门禁，而不是仅前端文本框。

### ISSUE-10 P1：立案表单的“负责律师”入口位置不符合一线习惯

**复现**：承办律师填写基本信息。

**实际结果**：主表单没有醒目的负责律师字段；只有右侧“团队指派（预览）”区域可选择，且完成度提示把它列为必填。

**影响**：用户会以为右侧仅用于查看，漏填后才发现无法继续。

**修复要求**：在“基本信息”或独立“团队”步骤放置带必填标记的“负责律师”字段；右侧只做摘要，不承载唯一编辑入口。

## 不作为通过项的范围

- 未验证律师 A/B 的真正隔离墙：当前本地环境没有可确认身份与职责的 A/B 试验账户，且 P0 所需“冲突核查人”角色尚未落地。不能以旧测试数据或猜测账户替代。
- 未验证主体变更后的阻断式重检、外部动作绑定、全量档案导入、加密存储与保留期限。这些依赖 PD-01 至 PD-07 的正式生效决策和后端状态机。
- “打印/导出 PDF”在自动化浏览器中未能完成点击分发，未作为功能失败结论；需在人工桌面验收中补测打印预览、脱敏范围和下载文件内容。

## 放行结论

本轮不能作为律师多用户冲突检查试用放行依据。严重命中阻断与管理端人工确认可用，但 ISSUE-01 至 ISSUE-05 都是 P0：涉及账户安全、最小披露、助理权限边界和冲突结论可靠性。完成这些 P0 并通过 A/B/核查人三角色回归后，才可进入受控试用验收。
