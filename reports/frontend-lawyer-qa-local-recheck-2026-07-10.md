## 4. P0 阻塞问题

### LQA-001 本案冲突复核会打开其他案件的检测任务

**复现路径**

1. 进入案件 `DEMO-MVP-2026-002`（案件 ID `35`）。
2. 点击“进入本案冲突复核”。
3. 页面带入 `case_id=35`、案件编号和案件标题。
4. 点击“查看本案检测结果”。

**实际结果**

页面提示已经匹配本案记录，但打开的是任务 `CC_1780554094583693000`，任务主题是另一条“AB 仿真冲突检查”案件。本案只是在该任务的 `conflict_cases` 命中明细中出现，并不是该任务的检测主体。

**律师风险**

律师可能针对错误的检测对象发起审批、申请豁免或停止承办，审批快照也会冻结错误记录。该问题属于案件级数据关联错误。

**工程定位**

`frontend/src/pages/batch01/Batch01Prototype.tsx:259-273` 的 `conflictMatchesCaseContext` 同时匹配任务主体和任务的 `conflict_cases` 命中项；`2401` 使用首个命中结果作为本案记录。命中案件被错误当成检测主体。

**验收标准**

- 本案上下文只能用检测任务的主体 `case_id` 做主匹配。
- 旧数据缺少 `case_id` 时，仅可使用经过规范化的主体案件编号做兼容匹配，不得使用命中明细反推主体。
- 标题不得作为独立唯一键；使用标题回退时必须同时核对客户或任务主体标识。
- 如果只有“本案被其他任务命中”的记录，页面应明确显示“本案作为冲突命中项出现”，不得显示“本案检测结果”。
- 发起审批前，前端和后端均校验 URL 案件与检测任务主体一致。

### LQA-002 “补充立案信息”打开无关旧草稿

**复现路径**

1. 在案件 `DEMO-MVP-2026-002` 详情点击“补充立案信息并重新检测”。
2. 或在冲突页无本案记录时点击“补充立案信息并检测”。

**实际结果**

统一跳转 `/case/create`，没有携带案件 ID。页面自动加载浏览器中的旧草稿“验收复测草稿-0528”，其客户、对方当事人和负责律师均不是当前案件上下文。

**律师风险**

律师以为在补充当前案件，实际可能修改并提交另一份草稿，产生错客户、错对方和错冲突检查。

**工程定位**

- 案件详情按钮在 `Batch01Prototype.tsx:1671-1672` 仅执行 `navigate('/case/create')`。
- 冲突页回补按钮在 `2517` 同样不携带案件上下文。
- 立案页在 `1755` 无条件读取固定 localStorage 键；`416-435` 没有案件或用户命名空间。

**验收标准**

- “补充当前案件”必须进入带 `case_id` 的编辑/补充模式，并从服务端读取该案件或接案记录。
- “新建案件”必须默认空表单；如检测到未完成草稿，应先展示草稿归属、更新时间，并让用户选择继续或放弃。
- 草稿至少按登录用户和接案 ID 隔离，不能使用全局单键覆盖所有案件。
- 页面标题和提交确认区持续显示当前编辑对象的案件编号。
- 服务端拒绝将不属于当前用户或上下文不一致的草稿提交到当前案件。

### LQA-003 冲突审核默认分配给申请律师本人，可形成自我审批

**证据类型：代码链路核验，本轮未执行最终审批写操作。**

**工程定位**

1. 前端 `Batch01Prototype.tsx:2465-2476` 创建冲突审核时，把当前登录用户同时写入 `applicant_id` 和 `current_approver_id`。
2. 后端 `internal/handlers/demo_aggregate_handler.go:671-699` 直接信任请求中的 `current_approver_id` 并写入审批表。
3. 前端 `Batch01Prototype.tsx:637-652` 在当前用户 ID 等于 `current_approver_id` 时开放同意、拒绝和退回权限。

**律师与合规风险**

申请律师可能审批自己的高风险冲突申请，绕过主任、合伙人或合规人员的独立复核。这不是展示问题，而是职责分离失效。

**验收标准**

- 前端不得提交或决定 `current_approver_id`。
- 后端根据审批类型、部门、风险级别和流程配置计算审批人。
- 后端强制校验 `applicant_id != current_approver_id`，并禁止申请人执行任何决定动作。
- 没有可用审批人时创建失败，返回明确业务错误，不得回退到申请人或固定 ID。
- 增加律师发起、主任审批的集成测试，以及伪造审批人字段的越权测试。

## 7. 已验证的正常行为

- 律师账号可登录，本地会话刷新后保持。
- 工作台主数据、案件数量、冲突任务和审批数量能够从本地 API 载入。
- 案件清单的状态筛选、关键词搜索和清除搜索可工作。
- 案件详情对待处理案件展示“下一步：利益冲突复核”。
- 冲突页默认是清单模式，不会自动弹出最近一次结果。
- 冲突详情可以打开、关闭，并显示风险、搜索参数和命中案件。
- 案件清单和冲突清单导出代码会生成本地 JSON，并设置成功消息。
- 立案取消确认框中的“继续编辑”和“返回案件清单”可工作。

上述正常行为不能抵消 P0 问题；特别是“能够打开冲突详情”不等于“打开的是本案正确的冲突详情”。

## 8. 未完成覆盖与原因

以下项目必须在修复 P0 后重新用 Chrome 人工执行，当前状态均为 `NOT RUN`，不能计入通过率：

1. 从空白新建案件开始，完整填写、保存草稿、刷新恢复、运行冲突检查、提交立案审批。
2. 正确选择一条高风险检测并创建冲突审批。
3. 律师只读审批页、主任审批通过/拒绝/退回、审批后关联案件生成。
4. 客户档案七个 Tab、联系人、附件、导出和快捷入口。
5. 个人中心修改密码和退出登录。
6. 顶部导航、侧栏所有入口及不同分辨率下的按钮覆盖。

中断原因是 Chrome 控制服务在立案表单操作中返回外部交互额度限制，不是被测系统报错。按照工具约束，本轮没有切换到其他浏览器或自动化工具规避限制。
