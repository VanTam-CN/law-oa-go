## 问题与修复记录

### QAN-001 工作台搜索缺少可见触发入口（已修复）

- 复现：输入案件名后不按回车，页面没有动作，也没有搜索提示。
- 根因：仅绑定 `onPressEnter`。
- 修复：改为带“搜索”按钮的 `Input.Search`，同时保留回车。

### QAN-002 审批关联案件可见但无权打开（已修复并实测）

- 复现：审批详情点击“查看关联案件”，案件详情提示无权。
- 根因：自动成案沿用过期配置中的律师 ID，且前端只按 `case_id` 判断可用。
- 修复：冲突任务负责人覆盖过期配置；接口返回 `accessible`；前端按可访问性禁用入口；迁移修复历史记录。
- 回归：律师 A 已成功打开案件 40。

### QAN-003 已成案案件仍要求重新冲突复核（已修复并实测）

- 根因：审批自动成案仍写入 `pending`，历史审批与案件状态未同步。
- 修复：审批生成案件写入 `active`；迁移同步历史审批、成案状态、说明和优先级。

### QAN-004 同名客户下拉无法区分（已修复）

- 复现：立案客户下拉出现两个完全相同的“上海示例科技有限公司”。
- 修复：仅在重名时追加邮箱、电话或客户 ID。

### QAN-005 冲突风险显示英文枚举（已修复）

- 复现：主区域显示“低风险”，侧栏显示 `LOW`。
- 修复：所有风险摘要统一走中文风险映射。

### QAN-006 未上传材料却显示“已收齐”（已修复）

- 根因：默认材料状态硬编码为 `received`，还会写入审批快照。
- 修复：默认状态改为“待补充”；未开放的文件管理入口明确禁用。

### QAN-007 “新增联系人”实际覆盖主联系人（已修复）

- 复现：点击“新增联系人”后表单预填原联系人，保存调用客户主档 PUT。
- 根因：当前 API 没有独立联系人资源。
- 修复：统一改名“编辑主联系人”，成功提示改为“主联系人已更新”。多联系人管理不在本次虚构实现。

### QAN-008 立案提交审批返回 `internal_error`（已修复并实测）

- 复现：低风险冲突检查完成后点击提交审批，页面停留并提示 `internal_error`。
- 根因：空字符串写入 PostgreSQL JSONB 字段 `conflict_result`。
- 修复：服务端默认写 `{}`；详细错误只记服务端；页面显示可行动的中文错误，并声明草稿仍保留。
- 回归：同一正式 API 环境成功创建审批 `AP-20260712-21000`。

### QAN-009 客户关联类型显示 `opposing_party`（已修复）

- 修复：关系图谱和列表统一映射为“对方当事人”等中文法律语义。

### QAN-010 待办来源显示 `case`（已修复）

- 修复：来源列映射为“案件任务”。待办查看详情与标记完成已实测成功。

### QAN-011 历史审批仍泄露旧演示身份（已修复并迁移）

- 复现：审批列表/详情显示旧邮箱和旧管理员名称。
- 根因：账号匿名化后，审批表中的冗余申请人/审批人名称没有随稳定用户 ID 刷新。
- 修复：迁移 47 以用户 ID 为权威回填申请人、当前审批人、审批记录；旧测试域邮箱改为中性历史示例身份。

### QAN-012 主任账号无法处理待审批单（已修复并实测）

- 复现：主任打开 `AP-20260601-924000`，页面提示“当前账号仅可查看审批进度”。
- 根因：部门负责人缺失时按最早创建时间选中系统保留管理员，未优先选择具备合伙人资历的可登录管理账号。
- 修复：默认管理员和部门审批人均按合伙人、高级、中级资历排序，匿名历史账号置后；移除硬编码系统管理员回退；迁移 48、50 将修复前生成的公开试用立案审批转交可登录主任。
- 回归：迁移修复的 `AP-20260712-21000` 成功成案；修复后全新创建的 `AP-20260712-724000` 无需迁移即直接分配给“示例管理员”，并生成 `CASE-20260712003544`。

### QAN-013 新建审批的案件类型丢失（已修复并实测）

- 复现：立案选择“商事诉讼”，审批和正式案件显示“其他”。
- 根因：前端提交时把规范枚举 `commercial` 先翻译成“商事”，详情页又把“商事”当作未知枚举。
- 修复：审批和成案配置始终提交规范枚举；显示函数兼容历史中文值；迁移 49 将存量中文类型规范化。
- 回归：存量修复后的案件 45 与修复后新生成的案件 46 均显示“商事”，新提交配置使用规范枚举。

### QAN-014 全量 E2E 的审批断言与当前界面不一致（已修复）

- 复现：全量回归中 2 项失败；一项用模糊文本命中两处只读提示，另一项要求已移除的“更多”按钮必须存在。
- 根因：测试仍基于旧审批布局，不代表当前用户可见契约。
- 修复：只读提示使用唯一底部状态选择器；按钮测试改为验证打印、关联案件入口存在，且不存在含糊的“更多操作”。
