# 律师视角前端复验记录 - 2026-05-26

## 测试环境

- 入口地址: `http://127.0.0.1:3003/`
- 浏览器: Chrome + Codex Browser 自动化
- 账号: `lawyer / Demo@2026`
- 数据源: 页面显示为“正式 API”
- 复验角色: 律师使用者
- 记录人: 工程师记录

## 覆盖范围

- 登录与工作台
- 工作台刷新、搜索、待办筛选、新建立案、查看全部入口
- 新建案件立案流程: 基本信息、当事人、相关方、标签、冲突检查
- 利益冲突检测结果页: 风险筛选、查看详情、创建冲突审核、导出入口
- 客户管理: 新增客户、客户列表、客户主档案、主档案 Tab、快捷操作
- 审批中心: 审批列表、审批详情、当前审批人和非当前审批人权限边界
- 个人中心: 修改密码校验
- 财务中心律师直访无权限状态

## 结论

本次复验确认上一轮部分修复有效: 登录、工作台搜索反馈、新建立案入口、正式新建页不再默认预填 demo 案件、新增客户落库、非当前审批人的律师审批详情只读、修改密码字段级校验、财务无权限说明均可用。

但从律师完整工作流看，仍存在阻断和可用性问题，尤其是立案流程中的“运行利益冲突检查”会跳出当前立案上下文，导致后续“团队与费用 / 文档与材料 / 立案提交”无法连续完成。

## 新发现问题

### QA-RC-001 P1: 立案流程运行利益冲突检查后跳出当前立案上下文

- 页面: `/case/create`
- 复现步骤:
  1. 律师从工作台点击“新建立案”。
  2. 填写案件名称、案件类型、业务领域、子领域、客户、对方当事人、相关方、标签和案情摘要。
  3. 点击“下一步”进入“利益冲突检查”。
  4. 点击“运行利益冲突检查”。
- 实际结果:
  - 页面跳转到 `/conflict` 的独立“利益冲突检测结果”页。
  - 结果页展示的是已有冲突任务，例如 `红杉资本投资管理咨询合同纠纷案 / PostgreSQL测试客户`，不是刚刚在立案流程中填写的复验案件。
  - 原立案流程中的“进入团队与费用”按钮不可达，用户无法继续完整立案。
- 期望结果:
  - 冲突检查应在 `/case/create` 当前工作流内完成，或至少带着当前草稿上下文返回。
  - 检查完成后应启用“进入团队与费用”，并保留当前案件草稿数据。
- 影响:
  - 律师无法完成完整新建立案工作流。
  - 这是当前最主要的端到端阻断。
- 建议责任范围:
  - `frontend/src/pages/batch01/Batch01Prototype.tsx`
  - 立案冲突检查调用和路由跳转逻辑

### QA-RC-002 P2: 工作台“查看全部”入口点击后没有明显导航或反馈

- 页面: `/dashboard`
- 复现步骤:
  1. 律师进入工作台。
  2. 在“利益冲突待复核”区域点击“查看全部”。
- 实际结果:
  - 点击动作完成，但 URL 仍停留在 `/dashboard`。
  - 页面没有出现可见的筛选、展开、toast 或跳转反馈。
- 期望结果:
  - 跳转到利益冲突列表页，或在当前区域展开完整列表，并给出明确状态变化。
- 影响:
  - 用户会认为按钮无效。

### QA-RC-003 P2: 审批中心列表右侧操作列在当前视口下不易访问

- 页面: `/approval`
- 复现步骤:
  1. 律师进入审批中心。
  2. 查看审批队列表格。
- 实际结果:
  - 表格右侧“操作 / 进入审批”列在当前浏览器可视区域右边缘被挤压或截断。
  - 用户需要额外横向定位才容易进入审批详情。
- 期望结果:
  - 操作列固定在右侧或表格容器内提供清晰横向滚动。
  - 关键操作不应在常见桌面视口下被截断。
- 影响:
  - 审批详情入口可发现性下降，影响律师处理审批。

### QA-RC-004 P2: 审批详情“当前审批人”和流程节点展示不一致

- 页面: `/approval/:id`
- 复现记录:
  - 第一条冲突审查审批详情顶部显示“当前审批人：demo.lawyer@example.test”。
  - 同页流程卡片中当前节点显示“合伙人决策（当前节点）/ 王合伙人”。
  - 底部向当前律师展示“同意并成案 / 拒绝 / 退回修改”。
- 实际问题:
  - 用户很难判断自己是否真的是当前审批人。
  - 权限判断和流程展示使用的当前审批人字段可能不一致。
- 期望结果:
  - 顶部当前审批人、流程当前节点、底部可操作权限应来自同一审批状态模型。
- 影响:
  - 审批权限可信度下降，可能造成误操作担忧。

### QA-RC-005 P2: 客户主档案快捷操作缺少明确结果反馈

- 页面: `/client`
- 复现步骤:
  1. 打开客户主档案。
  2. 点击快捷操作区的“新增联系人”“上传附件”“导出客户档案”。
- 实际结果:
  - 未观察到明确 modal、drawer、toast、下载确认或“功能建设中”提示。
  - 页面主要表现为焦点停留或滚动到相关内容区域。
- 期望结果:
  - “新增联系人”打开新增联系人表单。
  - “上传附件”打开上传控件或说明当前不可用。
  - “导出客户档案”触发下载，并在无法下载时给出提示。
- 影响:
  - 律师无法判断操作是否成功执行。

### QA-RC-006 P3: 部分按钮和文本的可访问名称重复，影响键盘/读屏和自动化稳定性

- 观察位置:
  - 冲突页存在多个“高风险 / 低风险”可点击或可读元素。
  - 客户页存在多个“联系人”和重复客户名称文本。
  - 审批页存在多行同名“进入审批”按钮。
- 实际影响:
  - 自动化和辅助技术需要额外上下文才能定位。
  - 普通鼠标用户影响较小，但对键盘、读屏和 E2E 稳定性不利。
- 期望结果:
  - 给重复按钮增加上下文，例如 `aria-label="筛选高风险"`、`aria-label="进入审批 AP-xxx"`。
