# 律师端小范围试用验收方案 v1.0

> **验收对象**：law-oa-go 律师端 MVP（Batch01 原型）
> **验收角色**：律师（lawyer）+ 律所主任/合伙人（审批视角）双角色验收
> **验收范围**：立案 → 冲突检查 → 审批 → 案件管理 → 工作台 → 客户档案 → 数据隔离
> **前置条件**：后端 API 运行中、种子数据已加载、前端 dev server 已启动、所有代码改动已提交

---

## 验收约定（RULE）

| 编号 | 约定 |
|------|------|
| RULE-001 | 所有验证均以 `lawyer` 角色登录，除非特别注明切换角色 |
| RULE-002 | 冲突检查无匹配记录时，系统显示明确提示并提供"返回案件详情"和"补充立案信息并检测"操作按钮 |
| RULE-003 | 全局按钮名唯一："更多客户操作"、"更多审批操作"、"更多处理方式"各仅出现一次 |
| RULE-004 | 冲突检查前置校验字段以页面实际错误提示为准（当前代码校验：案件名称、客户、对方当事人、负责律师、案件类型） |
| RULE-005 | 客户选择支持前端模糊搜索（`showSearch` + `optionFilterProp='label'`） |
| RULE-006 | 数据隔离验证（8.3）必须在真实 API 环境下执行，前端 mock 环境不可判定通过 |
| RULE-007 | 审批决策操作需使用主任/合伙人账号，且审批单状态为 `submitted` 或 `under_review` |

## 本轮验收三态分类

每个验证点严格属于以下三类之一：

| 分类 | 含义 | 标记 |
|------|------|------|
| **必须通过** | 验收阻塞项，失败 = 不发布 | `MUST` |
| **已知缺口** | 允许失败但需记录，发布时附带说明 | `GAP` |
| **不在范围** | 本轮不验证，列入后续 Sprint | `SKIP` |

**统计口径**：本文档共 60 个验收点（56 MUST + 3 GAP + 1 SKIP），分布在 12 个场景中。另有 8 项已知缺口（GAP 表）和 5 项不在范围（SKIP 表）。末尾结果模板中的示例行不计入验收点总数。

## 已知缺口（GAP）

以下为本轮验收的已知 MVP 遗留。发布时需附带说明，后续 Sprint 修复。

| 编号 | 缺陷 | 业务影响 | 建议优先级 |
|------|------|---------|-----------|
| GAP-001 | /inbox 为 MVP 占位页，无实际待办功能 | 律师无法查看待办列表 | P2 |
| GAP-002 | 团队与费用缺少"争议标的额"和"预估律师费"字段 | 影响收费管理和风险评级 | P1 |
| GAP-003 | 当事人无"诉讼地位"（原告/被告/第三人）字段 | 同名主体不同地位的冲突风险不同，冲突检测精度受限 | P1 |
| GAP-004 | 冲突检查强制要求负责律师（Step 2），无法在团队分配前独立运行 | 冲突检查流程与业务逻辑矛盾 | P1 |
| GAP-005 | 高风险冲突无硬阻断，律师可自行忽略强行立案 | 利益冲突红线失守 | P1 |
| GAP-006 | "申请豁免评估"按钮未接通后端 | 中低风险冲突豁免流程不可用 | P2 |
| GAP-007 | 审批被退回后无"编辑重新提交"入口，律师需重新建案 | 驳回闭环断裂，律师重复劳动 | P1 |
| GAP-008 | 表单数据无持久化（`React.useState`） | 页面刷新/关闭导致已填信息全部丢失 | P1 |

## 验收账号要求

| 角色 | 用途 | 数据要求 |
