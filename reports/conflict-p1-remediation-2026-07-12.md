# 利益冲突检查 P1 修复与验收记录

日期：2026-07-12  
范围：律师端接案、冲突检测任务、人工复核、豁免评估、对象权限和关联实体规则

## 1. P1 目标

P0 已解决确定性规则、证据链、伦理墙脱敏和人工复核门禁。P1 进一步解决：

1. 检测过程不能阻塞为单次长请求，必须可观察任务进度。
2. 客户、对方、相关方、案件类型、案件名称或负责律师变化后，旧结果必须失效。
3. 冲突候选和直接冲突必须进入可审计的处置状态，而不是停留在风险标签。
4. 豁免必须具有独立申请、独立复核、条件、期限和明确状态反写。
5. 普通律师不得读取其他律师的检测任务、冻结结果、复核或豁免资料。
6. 客户关系本身不能自动构成冲突；只有关系实体实际命中当前对方时才进入复核。

## 2. 已实现行为

### 2.1 异步检测与进度

- 接案页使用 `POST /api/v1/conflict/tasks` 创建任务。
- 通过 `GET /api/v1/conflict/tasks/:task_id/result` 轮询 `QUEUED/RUNNING/COMPLETED/FAILED`。
- 页面显示排队或检测中状态，并阻止重复点击创建并发任务。
- 后台任务记录进入冲突清单和工作台任务统计。

### 2.2 结果过期控制

- 对客户、对方、相关方、案件名称、案件类型和负责律师生成稳定输入指纹。
- 任一实质输入变化后，旧检测结果、旧接案决策和旧检索范围均标记为作废。
- “进入团队与费用”和提交审批在重新检测前保持禁用或被门禁拦截。
- 相关方仅调整显示顺序不会导致无意义的重复检测。

### 2.3 豁免状态机

- 冲突详情提供正式“申请豁免评估”表单。
- 申请必须包含理由、至少一项风险控制条件和有效期。
- 系统自动选择与申请人不同的合规、风控、主任、合伙人或管理员作为复核人。
- 申请人不得自批；普通用户不得处理未分配给自己的豁免。
- 状态流转：`BLOCKED/REVIEW_REQUIRED -> WAIVER_PENDING -> WAIVED/BLOCKED`。
- 批准时固化生效日、到期日和审批记录；到期后自动恢复 `BLOCKED`。
- 只有 `WAIVED` 可以解除直接冲突门禁，`UNDER_REVIEW/REJECTED/EXPIRED` 均不能继续接案。

### 2.4 对象级权限

- 异步任务状态和结果按任务所有者校验。
- 复核记录和豁免资料使用相同任务归属规则。
- 管理角色可以按职责查看；普通律师只能读取本人任务。
- 审批工作台的豁免数量对普通用户按申请人或指定复核人过滤。

### 2.5 关联实体规则

- 删除“存在客户关系即自动报冲突”的逻辑。
- 只有客户关系网络中的实体与当前对方实际匹配时才生成结果。
- 使用规则 `RELATED_ENTITY_ADVERSE_REVIEW`，匹配类型为 `RELATION`。
- 证据记录关系来源、当前对方、匹配实体、历史案件和更新时间。
- 关系命中只进入人工复核，不自动升级为已确认直接冲突。

### 2.6 数据可移植性

- 豁免模型中的 MySQL 专有 GORM `enum(...)` 类型改为 `varchar`。
- 合法状态、类型、优先级和期限由服务状态机白名单验证。
- 新增迁移 `000052_portable_waiver_workflow`，补偿 PostgreSQL 环境因旧版 MySQL 专用迁移未创建豁免表的问题。
- 补偿迁移不执行破坏性回滚，避免误删已由旧迁移创建的 MySQL 豁免历史。
- SQLite 实际仓库存储测试覆盖申请、查询、审批和冲突状态反写，为 PostgreSQL/MySQL 之外的测试环境提供可移植验证。
