# 律师视角内部浏览器复测记录 - 2026-05-26

## 测试环境

- 入口地址: `http://127.0.0.1:3003/`
- 浏览器: Codex 内部浏览器

## 覆盖路径

- 工作台: 页面加载、刷新、新建立案、查看全部待办、查看全部利益冲突。

- 利益冲突: 导出检测报告、创建冲突审核、进入审批详情。
- 审批详情: 顶部操作、查看关联案件、材料区 Tab、返回利益冲突检测台。
- 客户档案: 发起新案件、发起冲突检查、新增联系人、导出客户档案。

## 新发现或仍存在的问题

### IB-RT-001 P1: 立案冲突检查按钮在必填信息不完整时仍可运行，并产生混乱反馈

- 页面: `/case/create`
- 步骤:
  1. 从工作台点击“新建立案”。
  2. 选择客户 `示例科技有限公司`。
  3. 切到“团队与费用”选择负责律师 `陈示例 · 争议解决部`。
  4. 回到“利益冲突检查”，点击“运行利益冲突检查”。
- 实际结果:
  - 页面先显示“接案草稿已创建：INT-...”
  - 随后提示“案件名称不能为空”。
  - 冲突检查状态仍为“待检测 / 未检测”。
  - 按钮仍显示“进入团队与费用”，但用户并不知道当前草稿是否有效。
- 期望结果:
  - 如果案件名称等必填项缺失，应在点击前禁用“运行利益冲突检查”，或点击后只做字段级校验，不应创建草稿。
  - 如果已创建草稿，应明确说明草稿状态，并阻止进入后续步骤直到必填项补齐。
- 影响:
  - 律师会误以为冲突检查已开始或草稿已有效创建，实际状态却仍未检测。

### IB-RT-002 P2: 工作台“查看全部待办”点击无导航或可见反馈

- 页面: `/dashboard`
- 步骤: 点击“我的待办”区域的“查看全部待办”。
- 实际结果: URL 仍为 `/dashboard`，页面没有弹窗、展开、筛选变化或提示。
- 期望结果: 跳转到待办中心，或在当前页面展开完整待办并给出明确状态变化。
- 影响: 用户会认为按钮失效。

### IB-RT-003 P2: 工作台两个“查看全部”按钮仍容易被测试和辅助技术混淆

- 页面: `/dashboard`
- 观察:
  - 页面上有“查看全部待办”和“查看全部利益冲突待复核”两个按钮。
  - 按 `getByRole('button', { name: '查看全部' })` 仍可命中两个候选。
- 期望结果:
  - 可见文案或可访问名称应完全区分，例如“查看全部待办”“查看全部冲突任务”。
  - E2E 应使用精确名称或语义区域定位。
- 影响:
  - 对读屏、键盘导航和自动化稳定性仍不友好。

### IB-RT-004 P2: 审批详情“更多操作”重复，普通定位和用户认知都不清晰

- 页面: `/approval/:id`
- 实际结果:
  - 页面存在两个同名“更多操作”按钮。
  - 自动化按按钮名称点击会出现严格模式歧义。
- 期望结果:
  - 顶部按钮命名为“更多审批操作”。
  - 底部按钮命名为“更多处理方式”或增加明确 `aria-label`。
- 影响:
  - 用户不清楚两个按钮职责差异，E2E 也容易不稳定。

### IB-RT-005 P2: 审批详情“查看关联案件”可见但不可点击，缺少原因说明

- 页面: `/approval/:id`
- 实际结果:
  - “查看关联案件”按钮显示在顶部操作区。
  - 点击时工具反馈元素未启用，页面没有说明原因。
- 期望结果:
  - 如果没有关联案件，应禁用按钮并显示 tooltip 或文案说明。
  - 如果有关联案件，应跳转到案件详情。
- 影响:
  - 律师无法判断是权限问题、数据缺失还是系统故障。

### IB-RT-006 P2: 客户档案“新增联系人”和“导出客户档案”点击后无可见反馈

- 页面: `/client`
- 实际结果:
  - 点击“新增联系人”后未出现 modal/drawer，也没有联系人表单或 toast。
  - 点击“导出客户档案”后未出现下载、成功、失败或建设中提示。
- 期望结果:
  - “新增联系人”打开联系人表单。
  - “导出客户档案”触发下载或显示明确提示。
- 影响:
  - 律师无法判断操作是否已执行。

## 测试限制

内部浏览器当前文本输入能力受限，输入框写入会被虚拟剪贴板限制阻断。因此本轮内部浏览器重点覆盖点击、导航、下拉选择和按钮反馈；需要输入案件名称、对方当事人等完整表单的路径，仍以已通过的 Playwright E2E 作为补充验证。
