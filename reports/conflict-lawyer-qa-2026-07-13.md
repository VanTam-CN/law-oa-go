## 结论

冲突检测算法主链基本可用：完全一致的对方当事人能被识别为严重冲突，证据链能定位历史案件；输入变化会使旧结果失效；无命中主体可得到低风险结论并进入立案审批。

但当前仍存在终态可重复审批、终态文案互相冲突、主命中主体映射错误、低风险仍可重复发起冲突审批等问题。在 P0/P1 问题修复前，不建议将该版本作为无人陪同的正式冲突处置依据；可用于有专人支持、保留人工复核和书面冲突检查底稿的受控试用。

## 问题清单

### CF-QA-001 P0 已豁免任务可以重复创建审批

- 复现：打开“AB仿真冲突检查-对方为既有客户”，确认状态“已按条件豁免”，点击“发起冲突审批”。
- 实际：成功创建新审批 `3c5c46d6-18e7-4c79-b303-5015e7b71875`。
- 预期：已批准、已拒绝、已撤销等终态任务不得创建同类型审批；已有进行中审批时也应幂等返回原审批。
- 律师影响：同一冲突会出现多个互相竞争的决定，无法判断哪个结论有效。
- 验收标准：终态按钮隐藏或禁用；API 返回明确业务错误或原审批；并发请求只产生一条有效审批。

### CF-QA-002 P0/P1 已豁免页面同时给出相反指令

- 复现：查看上述已豁免任务详情。
- 实际：同时出现“可按批准条件继续接案”“已按条件豁免”，以及“建议暂停承办”“不得继续提交立案”“请发起冲突审批”。
- 预期：页面只根据当前有效处置终态给出一套决策和下一步。
- 律师影响：律师无法判断能否接案，属于核心合规指令冲突。
- 验收标准：建立单一 `disposition -> copy/actions/gate` 映射；WAIVED 仅显示批准条件、有效期和监督要求。

### CF-QA-003 P1 主命中主体和检索名称映射错误

- 复现：查看本轮严重任务 `CCT_1f39efe8-4339-457a-a220-efd9c8e6e758`。
- 实际：“主命中主体/匹配主体”显示历史案件标题“审批人规则最终回归-20260712”，“检索名称”显示我方客户；证据链中的冲突实体实际是“上海示例科技有限公司”。
- 预期：主命中主体为冲突实体，来源案件单独展示案件编号和标题。
- 律师影响：摘要会让律师误认冲突对象，降低结论可信度。
- 验收标准：摘要从最高风险证据的 `searched_subject/matched_subject` 生成；案件标题不得写入主体字段。

### CF-QA-004 P1 摘要未回填结构化证据字段

- 实际：摘要中的匹配方式、比对方法、主体角色、规则编号均为“未提供”，但证据链已有 `EXACT`、`CLIENT`、`DIRECT_ADVERSE_CURRENT_CLIENT`。
- 预期：摘要与主证据链字段一致。
- 验收标准：接口 DTO 和前端映射均有自动化测试，核对主证据四个字段。

### CF-QA-005 P1 其他相关方被重复规范化

- 复现：添加“示例关联控股有限公司”后运行严重和低风险检查。
- 实际：规范化主体中出现两条相同名称，角色分别为“待确认”和 `OPPOSING_PARTY`。
- 预期：同一输入只生成一个主体；角色应保留用户输入的“其他相关方”语义。
- 验收标准：请求构造和后端归一化按规范化名称、身份标识和角色去重；测试覆盖重复输入。

### CF-QA-006 P1 历史已豁免记录缺少证据快照

- 实际：已豁免任务显示规范化主体 0、证据链 0，却已有最终批准决定。
- 预期：批准冲突豁免必须冻结完整主体、命中、证据、申请理由、条件和审批记录。
- 验收标准：无完整快照的申请不得批准；旧数据明确标为“历史数据不完整”，不得伪装成完整审计记录。

### CF-QA-007 P1 严重风险的提交和复核入口反馈滞后或失效

- 实际：严重结果的“提交审批并等待成案”看起来可点击，点击后才显示阻断；页面出现两个同名“进入冲突清单发起复核”，实测其中一个点击后 URL 不变。
- 预期：严重终态下提交按钮预先禁用并说明原因；只保留一个可用复核入口，携带任务上下文跳转。
- 验收标准：按钮状态在结果完成时即时更新；点击复核进入 `/conflict` 并自动定位对应任务。

### CF-QA-008 P1 旧结果过期后仍残留旧严重处置

- 实际：步骤区已显示“旧结果作废”，但底部仍显示旧严重警告和复核入口。
- 预期：输入变化后所有区域统一进入 STALE 状态，不再展示旧风险处置动作。
- 验收标准：风险标签、底栏、提交门禁和侧栏均来自同一个有效结果状态选择器。

### CF-QA-009 P1 两个重检按钮行为不一致

- 实际：结果过期后，步骤内“运行利益冲突检查”无效果；必须点击底部“保存并进行利益冲突检查”才执行新检测。
- 预期：相同语义入口调用同一流程，或明确区分“仅检测已保存版本”和“保存最新输入并检测”。
- 验收标准：任一主入口均能对当前可见输入完成保存、创建任务、轮询和展示结果；失败有明确反馈。

### CF-QA-010 P1 低风险文案和审批动作与实际放行冲突

- 复现：查看本轮低风险、0 命中记录。
- 实际：仍显示“尚未完成人工复核，不得继续提交立案”和“必要时发起豁免审批”，但同一草稿已经成功提交立案审批。
- 预期：低风险页面说明“未发现可识别冲突、可提交立案审批”，并清楚声明检查范围和人工确认责任。
- 验收标准：CLEAR/LOW 不出现“不得提交”和豁免措辞；提交规则与页面文案一致。

### CF-QA-011 P1/P2 低风险可创建冗余冲突审批

- 实际：0 命中记录的“发起冲突审批”可用，并创建 `317b1391-bce5-443b-b425-cdfeb3c08117`；同一草稿已有立案审批。
- 预期：若低风险不要求独立审批，应隐藏入口；若允许自愿复核，应要求原因并防止与立案审批产生冲突状态。
- 验收标准：明确规则并实现幂等；同一检测任务不能无理由反复创建审批。

### CF-QA-012 P1 低风险冲突审批缺少双方主体

- 实际：审批详情的关联客户和对方当事人均显示“来自审批快照”占位文案。
- 预期：审批人能直接看到客户、对方、相关方以及对应身份标识。
- 验收标准：审批快照保存并展示主体名称；禁止以占位文案代替实际数据。

### CF-QA-013 P2 多个同名豁免入口

- 实际：详情内有两个同名“申请豁免评估”，加上侧栏共三个同名入口。
- 预期：每个任务仅保留一个主入口，或使用不同的可访问名称。
- 验收标准：同一视图中命令按钮 accessible name 唯一；E2E 使用角色和名称可唯一定位。

### CF-QA-014 P2 立案步骤无法就地核对证据

- 实际：“查看冲突检测审计信息”展开后只有任务编号，完整证据链只能去清单详情查看。
- 预期：立案步骤至少显示主命中实体、规则、匹配方式、来源案件和跳转详情入口。
- 验收标准：严重/中风险结果可在不离开立案上下文时核对主要证据。

### CF-QA-015 P2 筛选上下文与侧栏建议不一致

- 实际：筛选中风险或低风险时，侧栏仍显示全队列“检测到高风险冲突，建议暂停承办”。
- 预期：明确标注“全队列总体风险”，或在选中记录后按当前记录显示建议。
- 验收标准：任何建议都注明作用对象，不让律师把队列级建议误认为当前案件结论。

### CF-QA-016 P2 登录失败反馈观察项

- 实际：一次别名登录失败/服务波动时，按钮长时间保持 loading 且无可见错误。
- 预期：401、网络中断和超时均在限定时间内恢复按钮并给出可操作提示。
- 验收标准：分别覆盖无效账号、API 不可达、请求超时的前端测试。

## 建议修复顺序

1. 先修终态幂等与单一决策模型：CF-QA-001、002、007、008、010、011。
2. 再修证据与主体可信度：CF-QA-003、004、005、006、012。
3. 最后收敛入口和上下文：CF-QA-009、013、014、015、016。

## 回归门槛

- 同一检测任务在任何终态和并发条件下只能存在一条有效同类审批。
- 页面任一时刻只能给出一套接案决策，按钮状态、文案、API 门禁一致。
- 严重、中风险、低风险各准备一条完整结构化种子数据，逐字段核对主体和证据。
- 覆盖输入变化后的 STALE 状态、重检、审批快照和返回清单流程。
- 用律师与主任两个账号完成申请、独立审批、回到原案件的闭环。

上一节列出的 4 个残余 P2 均已解决并完成复验：

1. 自动结论字段缺失时不再显示含糊的“未提供”，改为不展示缺失字段，避免把缺失信息误读为结论。

### 真实 Chrome 最终发现与修复

最终无人陪同 Chrome 复验发现：当检测结果为 `CLEAR`、`LOW` 或零命中时，即使 `requestedParty` 或 `queryName` 携带客户名称，页面仍必须显示“无命中主体”，不能把请求中的客户名称误显示为命中主体。

该问题已修复，并在真实 Chrome 中验证冲突清单与打印预览：上述结果均显示“无命中主体”，报告内容未将客户请求名称冒充命中主体。

最终 Chrome 还修正并核对了清单“命中类型”语义：不再显示原始 `EXACT`，也不再把任务“已完成”误作命中类型；高风险显示“规范化名称完全一致”，`CLEAR` 显示“无命中”，`CLEAR` 证据概要显示“未发现可识别冲突”，打印报告复用同一语义。
