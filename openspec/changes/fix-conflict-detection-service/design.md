## Context

利益冲突检测是律师事务所管理系统的核心安全功能，用于防止律师代理存在利益冲突的案件。当前系统存在以下关键问题：

1. **后端处理器失效**: `conflict_handler_simple.go`只返回硬编码的模拟数据
2. **前端集成错误**: API调用和数据格式转换存在问题
3. **业务逻辑缺失**: 缺少真实的冲突检测算法和风险评估
4. **测试验证不足**: 无法验证冲突检测功能是否正常工作

根据`REALISTIC_CONFLICT_VERIFICATION_GUIDE.md`，系统需要支持多种冲突类型检测：
- 商业竞争冲突
- 法律对立关系冲突
- 股权纠纷冲突
- 知识产权冲突
- 服务纠纷冲突

## Goals / Non-Goals

### Goals
- 实现完整的利益冲突检测算法，支持多种冲突类型
- 修复前端API集成，确保数据流正确
- 提供准确的风险评估和冲突等级分类
- 建立完整的测试验证体系
- 确保系统性能和可靠性

### Non-Goals
- 不重构整个系统架构
- 不修改其他业务模块
- 不添加新的外部依赖
- 不改变现有的数据库表结构

## Decisions

### Decision 1: 后端处理器重写
**选择**: 完全重写`conflict_handler_simple.go`，实现真实的冲突检测逻辑
**理由**: 当前处理器只返回模拟数据，无法满足业务需求
**实现**:
- 实现基于数据库查询的冲突检测算法
- 支持多种搜索策略（客户历史、对方当事人、关联公司等）
- 提供详细的风险评估和冲突等级分类

### Decision 2: 数据库查询优化
**选择**: 使用GORM进行复杂的关联查询，避免N+1查询问题
**理由**: 需要查询律师历史案件、客户关联关系等复杂数据
**实现**:
- 使用GORM的Preload和Join优化查询性能
- 实现查询结果缓存机制
- 支持分页和排序功能

### Decision 3: 前端数据流修复
**选择**: 修复API调用和数据转换逻辑，确保前后端数据格式一致
**理由**: 当前存在数据格式不匹配问题，导致功能失效
**实现**:
- 统一前后端API响应格式
- 添加类型检查和数据验证
- 实现错误重试和降级机制

### Decision 4: 冲突检测算法
**选择**: 实现多层次的冲突检测算法
**理由**: 需要检测不同类型和严重程度的利益冲突
**实现**:
- 直接冲突检测：律师是否已代理对方当事人
- 关联公司检测：企业关联关系分析
- 行业竞争检测：同行业竞争对手识别
- 历史案件分析：律师历史案件类型分析

## Risks / Trade-offs

### Risk 1: 数据库性能影响
**风险**: 复杂的关联查询可能影响数据库性能
**缓解措施**:
- 实现查询结果缓存
- 使用数据库索引优化
- 支持异步查询和结果通知

### Risk 2: 数据一致性
**风险**: 并发情况下可能出现数据不一致
**缓解措施**:
- 使用数据库事务确保一致性
- 实现乐观锁机制
- 添加数据版本控制

### Trade-off 1: 复杂性 vs 功能完整性
**权衡**: 增加算法复杂性换取更准确的冲突检测
**决策**: 优先保证功能完整性，同时通过模块化设计控制复杂性

### Trade-off 2: 性能 vs 实时性
**权衡**: 实时检测可能影响系统性能
**决策**: 实现异步检测机制，支持后台处理和结果通知

## Technical Architecture

### 后端架构设计
```
冲突检测处理器 (ConflictHandler)
├── 冲突检测服务 (ConflictDetectionService)
├── 风险评估器 (RiskAssessment)
├── 查询优化器 (QueryOptimizer)
└── 缓存管理器 (CacheManager)
```

### 前端架构设计
```
冲突检测模块
├── API服务层 (ConflictAPIService)
├── 数据转换层 (DataTransformer)
├── 状态管理 (ConflictState)
└── UI组件 (ConflictComponents)
```

### 数据流设计
```
用户输入 → 前端验证 → API调用 → 后端处理 → 数据库查询 →
冲突分析 → 风险评估 → 结果返回 → 前端展示 → 用户确认
```

## Performance Considerations

- 使用数据库索引加速查询
- 实现查询结果缓存机制
