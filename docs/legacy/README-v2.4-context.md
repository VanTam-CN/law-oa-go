## 历史部署与技术债务

旧 README 的部署口径已经历多次收敛，不能当作当前部署说明：

- PostgreSQL 15+ 是当时生产 bootstrap 入口；MySQL 8 和 SQLite 仅保留历史兼容/开发叙事，未通过 P0 生产验收；
- Redis 仅作为 `cache` profile 可选增强，Elasticsearch/Kibana 默认不启动，数据库搜索是回退路径；
- Prometheus/Grafana/Jaeger 仅在 `observability` profile 显式启用；
- Helm Chart 已弃用，历史 Kubernetes 叙事指向 `k8s/` canonical manifests；
- 历史试用 SQL 覆盖多数据库方言，只允许在隔离测试库验证，禁止写入生产；
- 旧版 `/api/v1/conflict-v2/checks` 兼容服务在生产返回 `MVP_MODULE_UNAVAILABLE`，避免形成第二套冲突结论；
- 2026-08-24 归档移除旧 `deployments/docker-compose.prod.yml`，原因是其强制 MySQL+Redis 并引用不存在的根 `Dockerfile.prod`。

这些条目用于解释为什么旧部署材料不能继续作为当前事实。若要恢复或引用归档内容，先按归档索引核对
manifest、目标路径、校验和和当前消费者，再执行最小恢复；不得把归档校验通过解释为生产验证通过。

| 主题       | 旧叙事                                  | 债务处理口径                       |
| ---------- | --------------------------------------- | ---------------------------------- |
| 数据库     | PostgreSQL bootstrap；MySQL/SQLite 兼容 | 兼容路径需独立迁移验收，不默认生产 |
| 缓存/搜索  | Redis 可选；ES 默认关闭                 | 显式 profile 和回退路径            |
| Kubernetes | Helm 弃用，指向 `k8s/`                  | 以当前部署文档和 manifests 为准    |
| 演示数据   | 多方言历史试用 SQL                      | 只进隔离测试库，禁止生产           |
