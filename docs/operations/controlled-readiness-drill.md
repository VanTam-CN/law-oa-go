# 运维准备度受控演练手册

## 目标和边界

本手册用于在 QA 或 controlled_pilot 范围完成备份、恢复演练、故障负责人、升级和回滚五项控制的证据采集。页面评分只说明受控证据是否齐全，`production_ready` 始终为 `false`；生产放行必须另行通过 `production_external_evidence` 门禁。

演练不得使用真实客户数据。若必须验证脱敏后的恢复结果，应先记录来源、脱敏方式和审批人，并保留在离线档案中。

## 准备

1. 指定一名演练负责人和一名复核人。复核人必须是系统管理员、超级管理员或律所主任；compliance 只能查看，不能登记。
2. 建立独立档案位置，并决定证据引用格式。系统仅接受：
   - `archive://档案编号`
   - `ticket://工单编号`
   - `qa://QA记录编号`
   - `controlled-pilot://受控试点记录编号`
   - `https://档案域名/路径`
3. 备份 PostgreSQL 配置、上传文件目录、镜像或制品版本、演练开始/结束时间。记录不得包含密码、密钥、令牌或联系人个人手机号。

## 五项控制

### 1. backup 数据备份

在受控数据库上执行一次真实备份：

```bash
pg_dump --format=custom --file="${BACKUP_DIR}/law-oa-$(date -u +%Y%m%dT%H%M%SZ).dump" "${DATABASE_URL}"
shasum -a 256 "${BACKUP_DIR}"/*.dump
```

同时备份上传文件目录并生成校验值。档案中记录执行人、开始/结束时间、备份编号、字节数和 SHA-256。

### 2. restore_drill 恢复演练

把上述备份恢复到一个新的隔离数据库，禁止覆盖源库：

```bash
createdb "${DRILL_DATABASE}"
pg_restore --dbname="${DRILL_DATABASE}" --no-owner --no-privileges "${BACKUP_FILE}"
```

启动应用并连接隔离库，抽查登录、客户、案件、代管款和文件元数据。记录使用的备份编号、恢复环境、核心抽查结果、完成时间和复核人。

### 3. incident_owner 故障负责人

由律所书面确认首席负责人、备用负责人和升级路径。在受控环境发起一次通知测试，并记录测试时间、响应人和结果。系统只登记外部档案编号，不在页面保存电话号码或其他联系方式。

### 4. upgrade 升级验证

记录升级前后制品版本和数据库迁移版本。在受控环境完成升级后运行健康检查，并抽查案件创建、冲突检查、审批、文件和代管款流程。记录通过标准、异常暂停标准和复核结论。

### 5. rollback 回滚验证

先执行升级前备份点，再验证可退回的前一版本。回滚后确认迁移兼容、核心业务抽查可用、文件仍可打开，并记录回滚耗时、版本/制品编号、数据兼容说明和验证人。

## 登记

1. 以 `admin`、`super_admin` 或 `director` 登录，打开“运维准备度”。
2. 选择 `QA 环境` 或 `受控试点`，逐项登记复核时间、证据引用和简短说明。
3. 登记后刷新页面，确认最新证据生效且哈希链状态为 `verified`。历史登记不能更新；复验时追加新登记。
4. 五项全齐时，受控环境评分为 `7/10`。若出现 `failed` 或 `legacy-rows-present`，系统按 `0/7` fail-closed。

### 异常证据链恢复

`failed` 或 `legacy-rows-present` 不能通过继续追加登记自动恢复。恢复流程为：

1. 停止该 scope 的新证据登记，导出全部旧行并生成 SHA-256 保全档案；
2. 由系统管理员和复核人确认哪些行来自旧格式、哪些行存在篡改迹象，并形成书面处置记录；
3. 数据库管理员在受控维护窗口、备份后按变更流程移除不可校验的旧行；应用接口和历史业务数据不得承担删除职责；
4. 恢复服务后按五项控制重新执行/复核并追加新链；
5. 保留离线保全档案和生产门禁审查记录。若处置不能证明旧链来源，受控评分不得恢复为 `7/10`。

## 完成标准

- 五个控制均为“已有证据”；
- 每项证据都能通过引用编号在离线档案中复核；
- 追加证据哈希链校验为 `verified`；
- 恢复、升级和回滚均有明确时间、执行人、版本/备份编号和抽查结果；
- 没有任何生产环境成功或生产放行结论。
