| 应用 | 重验服务端上下文；比较生成基线与应用当刻摘要，含等待期间人工改动和清空。变动必须重新对比并明确确认 |
| 人工变化 | 不冒充候选精确来源；已选来源失效后须重新应用有效候选或明确选择“改为人工摘要保存（不关联来源）” |

| 来源接受 | 浏览器只传选择，不传可信源包；服务端在 PG 原键锁及当前行版本检查后，用短内存锁冻结候选，随后释放内存锁再写库 |
| 原子保存 | 摘要、当前来源关联、不可变快照和终态回执同一 PG 事务。只用 `jsonb_set` 更新保留路径，未知大整数/小数不会经过 float64 重写 |

| 重放 | 已提交/no_change 先检查原回执和原参数摘要，再返原结果；不依赖临时上下文存活或当前业务版本仍相同。当前权限仍需有效 |

| 来源快照 | 原句、来源 ID、录入轮次、录入账号、服务器接受时间、候选与原版本、核对账号/时间。仅表示录入和核对来源，不证明案情真实 |
| 内容禁记 | 接案/助手路径在审计读取正文前排除内容，普通 HTTP 日志不写该路径 query/UA/错误正文，敏感数据库会话禁 SQL；实际主程序连接池及普通连接均参数化。对话/源包/候选授权不放浏览器存储；已应用摘要仍可能通过原生草稿缓存留存录入原句 |

## 3. 兼容边界及未决项

本切片不实现完整 `party_changes`、metadata 路径编辑或标题候选。无来源历史的旧表单仍按 final5 原生版本合同办理；它本身已强制 expected_revision、事务行锁比较及版本推进。有任何来源历史的记录拒绝旧全量更新，防止旧 metadata/主体数组旁路破坏关联。这样的记录在本候选只能走摘要局部更新，其他控件暂不具备完整迁移能力。

这是首切片受控开发边界，不能作为完整 G01 的兼容放行。已知共用保存入口剩余字段迁移、未知/外部旧调用实际登记和停用范围，继续留在完整窄版的 G00/G01/G04 跟踪。试点参加者只能验摘要场景，不能将本分支直接替换现网进行全业务办理。

五类状态写入、异步迟到检测、全模板、跨角色来源阅读、真实模型与预算、重启和升级回滚演练均未由首切片覆盖。开发合同具备本切片开工条件，不代表完整 NP-G00～G05 或 A01～A40 已通过。

## 4. 隔离执行合同

- 新 Compose 项目 `np-first-slice`，PG 16.14，实际库 `np_first_slice_dev`，Redis 独立卷；只映射回环 18790/18791。没有连接试用服务器。
- 为本机 Go 联调，原“PG 无宿主映射”准备项调整为仅 `127.0.0.1` 临时映射，避免复用或误连既有服务。
- 显式 bootstrap 后仅四个 final5 追加迁移，再单独执行 `000086_narrow_pilot.up.sql`；没有全量历史 migrate up、自动生产迁移或破坏性 down。
- 本地 `np_local_check` 构建标签的检查入口复用实际 router，固定回环 18789、虚构夹具，不执行 root main 的开发 AutoMigrate。它不包含在普通构建中。
- 浏览器只用回环 3003、新上下文、固定隔离 API 代理且禁止复用既有前端。
- 实际断线包括：PG 已提交而客户端未收响应的 TCP 关闭；PG 行锁等待时切断客户端连接；浏览器经本地检查入口实际关闭上游 socket 后重登回查。测试专用故障入口仅存在于受保护的构建标签程序。
- 开放试用前仍需同候选升级/回滚各一次、全过程最多一个助手实例、前后端匹配和未决回执/来源可查。此项未执行，不能以当前本地单实例点验代替。

运行证据和最终候选见 `np-first-slice-review.md`；原始首失败和最终检查输出在 `np-evidence/`，不提交含 token 的浏览器 trace。
