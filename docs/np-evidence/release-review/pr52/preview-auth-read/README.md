# 4173 构建预览的真实登录与业务读取

本卡接续[普通 E2E 验收](../e2e-full/README.md)。上轮 115 个用例访问 3003 的 Vite 开发服务，4173 只验证了预览首页的 HTTP 状态。本卡固定同一候选 `f3cd764d0bc7f82efb2b012669132f5b89e3d15c`，验证浏览器打开生产式构建预览后，能以合成账号登录并从真实后台读到对应的业务对象。Hermes 卡为 `t_6189137f`。

## 证据口径

| 环节 | 判定依据 |
| --- | --- |
| 构建预览 | 在隔离 runner 构建候选的前端，通过 4173 打开页面，检查实际构建资产。 |
| 身份 | 使用全新浏览器上下文，在真实登录表单提交一次性合成凭据。核对登录接口结果和预期用户身份。 |
| 业务对象 | 在原生页面选取本次种下的对象，比对同源详情响应中的对象与数据库种子，再核对页面渲染。 |
| 数据保全 | 在浏览器读取前后分别从同一合成数据库取证，核对目标和对照对象及关联业务行。真实登录允许产生会话等认证侧记录。 |

## 首轮失败与复跑口径

[首轮托管作业](https://github.com/VanTam-CN/law-oa-go/actions/runs/45791095259/job/139810016262)在登录、律师身份、草稿 ID、标题和摘要均符合预期后，报出 `REVISION_MISMATCH`。固定候选的详情接口将版本放在 `data.revision`，首轮探针读了 `data.intake.revision`。该次未执行读后的 PG 比较。

[验证脚本修订](https://github.com/VanTam-CN/law-oa-go/commit/291616e0e4be6dff21343401e053d90620ef6197)按接口实际字段与 PG 版本对照。主体数与材料数均直接从目标草稿查询，同源断言覆盖登录及详情调用。两轮在检出固定候选后构建，差异仅涉及验证工作流与浏览器探针。

详情路由经过 `AuthMiddleware`，详情处理器检查当前操作人可见范围。浏览器从空上下文经原生登录进入工作台，在列表中选中本轮生成的目标草稿；账号、密码、令牌、正文和行快照均未纳入证据归档。
