## 只读盘点与隔离决定

GLM 使用既有账户和公钥，通过已有主机指纹校验登录。现有账户可通过 sudo 非交互访问 Docker。原 Compose 项目有四个运行中的服务：应用、PG16、Redis 和 Caddy。应用端口绑定回环地址，代理绑定局域网地址，数据库和 Redis 只在原容器网络内监听。原项目使用绑定挂载保存数据库、上传文件和缓存等状态。主机有 8 核、约 13 GiB 可用内存，数据盘剩余约 272 GiB，根盘剩余约 4.6 GiB。

本轮使用数据盘上的独占目录、无外部网络的测试容器和内存中的全新 PG15。容器对宿主机发布端口数为零，唯一的目录绑定为本轮从 Git 导出的只读迁移文件。服务、预览和浏览器在该容器的网络命名空间中使用回环端口 8080、4173、18790。没有使用原项目的数据库、卷、凭据、镜像或前端资产。

## 构建与实际运行

协调者从干净的固定提交构建 ARM64 Go 服务和迁移程序，使用 Go 1.25.6、CGO=0；前端使用 Node 22.17.0、锁文件和 Vite 的正常生产构建。构建产物在本机生成，GLM 在目标主机按清单校验 SHA-256。目标主机实际运行 Node 20.19.5、Playwright 1.60.0 和 revision 1223 的 Linux ARM64 Chromium，浏览器报告 148.0.7778.0。

## 原实例状态的判定口径

快照涵盖原四个容器的 ID、镜像、启动时间、重启计数、运行状态、端口、挂载及网络 ID。Docker 两次返回的挂载数组顺序不同。协调者固定其他字段，仅排列同一容器的挂载项，共 48 种组合，核对各采样点的原始指纹均可重现。结论限于所采集的容器字段和测试资源隔离；没有读取原数据库内容，也没有测试原业务代理的全时段可用性。

最终采样的原始指纹与运行前也完全相同。协调者经 SSH 确认两个临时目录均不存在、带本轮标签的容器数为零，三个测试端口均无监听。Docker 事件中可见一次 PG15 基础镜像导入；无法确认导入前该无标签缓存是否已经存在，因此保留缓存。
