## 修改前的实测

协调者在 Go 1.25.0、Linux/arm64、无宿主端口的 PostgreSQL 16.14 和 Redis 7 环境中运行整包 `-benchtime=1x`。四个 API 场景均失败于 HTTP 404。数据库简单查询也失败，首个数据库错误是 1,000 条用户的用户名重复，夹具忽略写入错误后继续查询不存在的记录。另有子基准打印了用时，但原代码没有验证它们是否进入预期处理器。

| 独立路由探针 | 注册结果 | 请求结果 |
| --- | --- | --- |
| SQLite | 初始化失败，0 条路由 | 原路径和版本化路径均返回 404 |
| 新建 PostgreSQL，无 000086 | 初始化失败，0 条路由 | 来源与回执表结构未满足要求 |
| 同一 PostgreSQL，完成基线及冻结的 000086 | 初始化成功，注册 355 条路由 | 旧 `/api/cases` 返回 404，正式 `/api/v1/cases` 在无凭证时返回 401，健康检查返回 200 |

Astra 从基线源码独立核对了正式路由、认证和 schema 要求。19 个叶子基准在 PGO 中原定各运行 30 秒，单次迭代只用于核验功能，托管采样与构建另行判定。

## 夹具与验收口径

两项 CI 作业在各自 runner 上准备 PostgreSQL、独立 Redis 和一次性基准库。数据库从已执行冻结迁移 000086 的模板克隆。四个 API 子项和四组并发请求使用正式路由、合成律师真实登录产生的 token。计时前检查律师身份、案件及客户记录、仪表盘数量，以及匿名访问时的 401。每次请求必须得到 200。数据库查询另用 1,000 个唯一用户名的 SQLite 内存库，验证查询结果。Redis 读取验证预置值，管线检查命令完成数。缓存、性能计数、限流和 CORS 分别执行其对应中间件。

协调者复跑原工作负载的 19 个子项。单次与竞态检测双次运行均通过，250ms 采样的 19 项各有正迭代数。Go 工具成功读取并合成 CPU 和内存 profile。普通测试在移除夹具环境变量后通过。缺专用 DSN、空 PG 缺 000086 两个对照各自失败。再次查询 PG 时，原有对照行摘要一致，本次用户、案件、客户和数据库令牌会话均已清理，Redis 对照值也保持一致。逐项迭代数见[结构证据](verification.json)。这些短时运行用于核验夹具和证据链，未设置性能目标。

Astra 复现了跨包同名误计。协调者独立构造两个 Go 包，目标包跳过 GetCases 时全库命令退出 0，但修订后的证据检查退出 1，准确指出缺少该项。恢复目标包用例后提取 19 项。全库命令仍运行所有包，检查器只接收目标包内的结果并要求该包正常结束；其他包失败仍会使作业失败。

缓存命中基准度量预写缓存的读取、状态、标记头和正文。协调者另用带下游处理器的 Gin 链实测，命中时仍会进入下游，原短路断言失败。该问题由 Hermes `t_af5c899a` 单独跟踪。未从此基准推定线上命中率、回填效果或下游短路行为。

协调者另从最终提交的干净归档构建根程序。标准构建使用 `-pgo=off`，优化构建使用上述 250ms 工作负载的 CPU profile。两个进程先后在私有容器网络使用专用合成数据库，各完成 50 次 HTTP 200 的存活检查并退出。这是本地短时采样与启动验证，托管作业使用自己的 30 秒采样。
