## 接案编号碰撞的裁决

`CreateCaseIntake` 在 main 与应用候选中均按秒生成 `INT-` 编号。原生新建在同一秒可触发 PG 唯一约束，一方收到 500。M5 已记录真实隔离故障；Hermes 复现子卡 `t_f2da0642` 另报 5 组、每组 12 路，每组 1 个 201、11 个 500。后者是既有子卡记录，本轮没有重发创建请求。[M5 首次观察](../m5/README.md) · [候选生成逻辑](../../../internal/handlers/demo_aggregate_handler.go)

- **只改已有草稿。** 已有草稿的 PUT 和回查不生成新接案编号。若能确认参与者、预置草稿、原生入口及同环境的其他使用者都能在约定范围内运行，负责人可书面接受已有风险。该缺陷单项不阻塞此范围。仅限制助手白名单仍允许原生新建，不能据此认定风险已隔离。
- **需要新建，或无法排除对日常新建业务的影响。** 阻塞相应试用。错开操作时间不能作为并发保证。新建风险与既有草稿的幂等回执、审批号碰撞分别跟踪。
- **已有可审修复。** 复核本地 Git 对象，修复 `a9a5116` 与回归 `a7ded85` 从 `04bcce9` 分出，均未进入已验候选或远端 main。两张子卡分别记录修复后 60/60 成功及 PG 并发回归；这两条旁支的远端同名分支在此次查询中无返回。纳入试用时先绑定新的集成 SHA，复审编号兼容、受限重试及事务，确认实际 PG 测试执行且无 Skip、编号互异、非目标唯一键错误维持原语义，同时复验受影响的原生办理路径。原卡 `t_a4646b57` 继续承接处置。
