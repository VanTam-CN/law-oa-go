复核时，独立的 20 项回查/放弃矩阵首次出现 10 红，原因是终态缺少对象或有效版本仍被接受，修订后 20/20。浏览器首次应用候选后没有发出 PUT，定位到详情恢复丢弃服务端 created_by，已修复。数据库中账号角色改变时，旧版全量请求曾返回 409，现已在接案锁内复核当次身份，再决定是否返回版本或协议提示。原有 M1 锁等待用例使用已登记的合成会话，继续强断言 409、协议错误码和 PG 内容保全。

复跑采用独占的回环 PG、v14 基线及受控 86 迁移。先运行 PG 组，再用 `compare-main-browser-db.py seed` 建新用户和目标/对照行，`before` 固定基线。将同一 manifest 提供给带 `np_local_check` 标签的服务和 Playwright。四场景一次串行通过后，由 `after` 比对同一窗口。口令只由本地测试环境提供。仓库证据只含汇总。
