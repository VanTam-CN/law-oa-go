首红提交 `e55c5f3` 仅含测试。普通别名及平铺审批作正对照，四个 PG 业务场景和一个 Chrome 场景在修复前失败。复核另发现字符串空数组的历史格式，在 `09bb6f2` 单独固定失败后修复。中途全组回归另有两条脱敏用例绑定旧的 Go 浮点类型，现对 HTTP 序列化数字逐字核对，原敏感字段过滤断言保留。

隔离环境使用一次性 PostgreSQL 16.14、基础迁移和受控 86 号追加，仅使用合成身份与案情。审批贯通由 `scripts/np-first-slice/verify-m1-browser-approval.sh` 协调 Chrome 与临时 PG 路由。恢复、保存和检测的浏览器响应由 fixture 提供，审批请求体直通，鉴权使用合成律师令牌。Go 集成用例通过真实仓储和登记路由单独核验检测与保存。Go、构建、Jest、浏览器及贯通用例的命令、提交、起止时间、退出码、逐项结果和日志摘要见 [结构化证据](verification.json)。

浏览器数字回显存在一个固有歧义。原值超出 JavaScript 安全整数范围时，旧客户端如果提交的恰好是原值的舍入结果，服务端保留原值。这项兼容规则用于已有字段，其他可区分的新数值仍可编辑。
