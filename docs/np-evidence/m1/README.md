## 复跑条件

使用空闲的本机回环端口 18790 和仅用于本测试的 PostgreSQL 16.14 临时容器。数据库名须为 `np_first_slice_dev`，用户为 `np_m1`。运行 `go run ./cmd/migrate -command bootstrap` 时显式提供 DB_DRIVER、DB_HOST、DB_PORT、DB_DATABASE、DB_USERNAME、DB_PASSWORD、DB_SSLMODE；测试口令取非空合成值。随后运行 `scripts/np-first-slice/apply-main-np86.sh`。受控脚本与带 `np_m1_pg` 标签的集成测试均限定本机合成目标。负向门禁用临时表改名构造，不能在共享库复跑。

在仓库根执行证据中的 Go 命令。浏览器命令在 `frontend/` 执行，使用 lockfile 对应的依赖、系统 Chrome 和专用 Playwright 配置。配置启动只监听回环 18793 的独立 Vite；浏览器使用模拟 API。真实路由、授权、锁等待与事务回滚由 Go / PG 测试单独验证。前端构建输出目录可替换为空的本地临时目录。

本次覆盖 M1 作者集成及主调度复核。冻结的 M0 矩阵保留原历史记录。I14 的助手严格写入、I15-NP、正式 main + Redis、缓存与旧标签页、升级回滚单实例、真人试用和独立验收仍由后续阶段承担。旧全量 PUT 调用方必须随请求带回读取的版本；外部调用方迁移情况待核验。该候选的共享启动路径要求已具备 86 号结构的 PostgreSQL。两版材料文件依旧后置。
