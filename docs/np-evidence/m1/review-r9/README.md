# M1 R9 原生数组保存验收

复核起点为 `f1f6889`。只含测试的 `4ed257b` 在新建的本机 PostgreSQL 16.14 合成库上得到 8 个失败叶用例，原 14 个对照通过。验收源码为 `493ad9e`。Hermes 修复卡 `t_8eeb51b2` 的父卡 `t_53c0e6f9` 保留上一轮独立反例。

| 场景 | 首红 | 修复后，两条原生保存路径 |
|---|---|---|
| 仅交换对象，GET 隐去其中一个对象的 external_identifier | 200，字段落库消失并升版；文本隐藏值且完全没有大整数的变体也失败 | 409 / INTAKE_METADATA_ARRAY_AMBIGUOUS。接案和主体两行（含同时提交的标题改动）以及草稿版本均与保存前相同 |
| 删项后追加，另一对象的字段恰等于大整数的浏览器舍入值 | 对象位于前缀或后缀均误拒 409 | 均为 200 并升版；独立从保存前 PG 数组计算预期并逐项比对，原大整数、对象及追加项均正确，另一入口的数组原值保留 |
| 无损客户端明确回传两个不同大整数 | 调度复核的中间候选把它们归入同一浏览器表示而误拒 | 接案补充用例在请求中保留精确字面量，200，按新顺序精确保存 |

共享恢复函数按完整数组元素的 GET 表示查找可能移动的旧元素，再把兼容来源的完整数据库值和准备写入的值比较。隐藏字段属于原对象，旁边对象内部的单个数字不会成为另一个数组元素的候选来源。位置解释与左移解释仍分别核对。完整请求显式携带精确数字时，比较实际传入的数字。已有的单元素替换与内层追加同形边界沿用 R8 约定，两条替换意图探针单列为预期失败。

[运行证据](verification.json) 记录固定提交、命令、实际观察、起止时间、退出码和日志散列。Go -race 主矩阵 165 项通过、0 失败、0 跳过（计数含父测试）。另跑 V8 对原生 GET 结果实际编辑再 PUT 的 16 个 R9 叶用例，包括中间位置交换、嵌套隐藏对象交换、同投影对象原样回传、前后缀及普通数值对照。原 R6/R7 补充矩阵和 84 组精度输入也已复跑。
