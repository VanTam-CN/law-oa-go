# M1 R10 原生全量保存与独立复核

R9 复审对象为 `ce8c79c`（应用 `493ad9e`）。Astra 用固定提交检查共享恢复逻辑，协调者用合成 PG 16.14、实际 GET/PUT、V8 编辑和保存前快照验证两个入口。R9 原报的隐藏对象交换及 mixed prefix/suffix 均符合预期。以下扩展对照使 R9 保持 HOLD，并在同一开发分支继续修复。

| 路径 | 修复前观测 | R10 验收口径 |
|---|---|---|
| 只改标题，原样回传同时具有父子两层隐藏字段的对象 | 两个版本均升版，外层隐藏字段消失；单层对照完整 | 200，原对象完整保存，另一入口数组不变。修改旁边的普通值也应成功 |
| 把首个子数组移到末尾后追加；与删首再新建产生相同请求 | `f1f6889` 为 409，`ce8c79c` 两个入口均为 200 并写入舍入值 | 精确解释冲突时返回 409；普通整数对照精确保存 |
| 跨子数组交换或剪切带隐藏字段的完整对象 | 收缩的数组与增长的数组各自恢复时，目标只有脱敏值；仅保护顶层键也会漏掉位于 child 的隐藏字段 | 有歧义的请求返回 409；明确删除和无隐藏字段移动均为 200。另一个未改对象中的空子对象不应导致误拒 |
| 修改本身携带隐藏字段的对象可见内容 | 旧版可能遗失隐藏值；相同字段名不足以确认是同一对象 | 对无法确认身份的替换返回原生歧义码；禁止静默去掉隐藏信息或将其带给另一个对象 |

拒绝路径同时断言原生业务错误码 `INTAKE_METADATA_ARRAY_AMBIGUOUS`、接案整行、主体整行、草稿版本，以及同请求标题修改回滚。成功路径从保存前 PG 数据独立构建预期值，检查落库内容和升版。已有的单元素替换与内层追加同形约定沿用 R8，两条替换意图探针继续单列。

`5ce60fa`、`ccef6f1` 固化了第一组反例。首个实现 `b774a29` 先比对完整 GET 回传，再恢复子对象，并核对移动后增长的尾项是否仍保留来源的精确值。独立复核发现跨数组移动仍能绕过局部检查。`7de7a8c`、`7bdad09` 固化剪切移动、隐藏子键和可判定的对照。最终源码 `89bb420` 在一个 metadata 字段内核对发生位移的受保护对象，按 GET 投影定位可能来源，再比对完整存储值。对完整字段内部的嵌套对象及数组使用同一检查。

glm-flash 提供的候选按键结构合并，调度复核判定这种做法可能将隐藏字段绑定到新对象。最终实现选择保留可核对的原对象，在解释冲突时整笔拒写。Hermes R9 复审卡为 `t_9f7f8a37`，R10 修复卡为 `t_8d64d0d6`。
