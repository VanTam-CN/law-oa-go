## 🐹 Go 代码检查项

### 代码规范

- [ ] **包导入**: 导入顺序正确（标准库 → 第三方 → 内部包）
- [ ] **接收器命名**: 方法接收器使用一致的短名称
- [ ] **错误变量**: 错误变量以 `Err` 开头
- [ ] **常量定义**: 使用 `const` 块定义相关常量
- [ ] **接口命名**: 单方法接口以 `-er` 结尾

### 错误处理

- [ ] **错误检查**: 所有可能返回错误的函数调用都被检查
- [ ] **错误包装**: 使用 `fmt.Errorf` 和 `%w` 包装错误
- [ ] **错误类型**: 定义了适当的错误类型和变量
- [ ] **错误上下文**: 错误信息包含足够的上下文信息
- [ ] **错误日志**: 在适当的层级记录错误日志

```go
// ✅ 好的错误处理示例
func (s *UserService) CreateUser(ctx context.Context, req *CreateUserRequest) (*User, error) {
    if err := s.validateUser(req); err != nil {
        return nil, fmt.Errorf("user validation failed: %w", err)
    }

    user, err := s.userRepo.Create(ctx, req.ToUser())
    if err != nil {
        s.logger.WithError(err).Error("Failed to create user in database")
        return nil, fmt.Errorf("failed to create user: %w", err)
    }

    return user, nil
}
```

### 测试质量

- [ ] **测试命名**: 测试名称描述清楚测试内容
- [ ] **测试结构**: 使用 AAA 模式（Arrange, Act, Assert）
- [ ] **测试独立**: 测试之间相互独立，可以单独运行
- [ ] **Mock 使用**: 合理使用 Mock，不过度 Mock
- [ ] **测试数据**: 使用有意义的测试数据

```go
// ✅ 好的测试示例
func TestUserService_CreateUser_Success(t *testing.T) {
    // Arrange
    mockRepo := &MockUserRepository{}
    service := NewUserService(mockRepo)
    req := &CreateUserRequest{
        Name:     "Test User",
        Email:    "test@example.com",
        Password: "password123",
        Role:     UserRoleLawyer,
    }
    
    mockRepo.On("Create", mock.Anything, mock.Anything).Return(nil)
    
    // Act
    user, err := service.CreateUser(context.Background(), req)
    
    // Assert
    assert.NoError(t, err)
    assert.NotNil(t, user)
    assert.Equal(t, req.Name, user.Name)
    assert.Equal(t, req.Email, user.Email)
    mockRepo.AssertExpectations(t)
}
```

## 🎯 审查流程

### 1. 自检阶段

开发者在提交 PR 前应该：
- [ ] 运行所有测试并确保通过
- [ ] 使用工具进行代码检查（golangci-lint, ESLint）
- [ ] 自行检查本清单中的关键项目
- [ ] 确保代码符合项目规范

### 2. 同行审查

审查者应该：
- [ ] 检查代码逻辑正确性
- [ ] 验证测试覆盖率和质量
- [ ] 确认安全性考虑
- [ ] 评估性能影响
- [ ] 检查文档完整性

### 3. 最终检查

在合并前：
- [ ] 所有自动化检查通过
- [ ] 至少一位审查者批准
- [ ] 解决所有审查意见
- [ ] 更新相关文档
- [ ] 确认部署计划

## 📈 质量评分

### 评分标准

每个检查项按重要性分为三个等级：

**🔴 关键项 (Critical)** - 必须修复
- 安全漏洞
- 功能错误
- 性能问题
- 测试失败

**🟡 重要项 (Major)** - 应该修复
- 代码规范违反
- 设计问题
- 文档缺失
- 轻微性能问题

**🟢 建议项 (Minor)** - 可以改进
- 代码风格
- 命名优化
- 注释改进
- 小的重构建议

### 通过标准

- 🔴 关键项：0 个未解决
- 🟡 重要项：≤ 2 个未解决
- 🟢 建议项：≤ 5 个未解决
- 整体评分：≥ 8.0/10
