优先级在本报告中指“实现相应闭环前必须解决”，不表示已在生产复现漏洞。源码推导出的失效路径均单列为静态风险。

## 4. 窄版落地必须明确的契约

详细字段表、写入清单及物理结构建议见附录清单。以下为本次建议的收敛结果，尚未实施。

### 4.1 保存链路与已放弃回执

业务保存继续只有原生 POST/PUT；创建/更新分开 DTO，权限、真实变化、revision、来源和回执在接案应用服务统一。不新增助手写执行器。原生人员助理 assistant_draft 的无客户及字段限制不套用律师试点条件；原生接手是否共享池由 G00 业务确认，不默认视为存在指派关系。

所有原生保存和明确放弃共用 actor+原键的 PG 事务级锁/唯一约束。业务写前锁内主库读终态；已有 committed/no_change 重验当前访问权后按原请求返回，abandoned 则拒绝所有迟到旧键写入。GET 只读查结果；查不到只表示 unknown。

用户明确调用 POST abandon 时，同一锁内若已有成功则返回成功，若无终态才提交 abandoned；未取得锁、数据库失败或放弃提交结果未明，不准新键。墓碑允许原请求摘要为空，不虚构未知正文；试点不随上下文 TTL 删除。新登录可用最小请求/动作/对象范围继续处理，不需要丢失的上下文。这是原生幂等收口，不是通用运行平台。

源码 h.db.Table/Transaction 未绑定请求 Context、主 HTTP Server 无 WriteTimeout 只支持“断线仍可能提交”的路径判断，不支持“已真实复现竞态”。A27 必须运行真实断线与可提交窗口，记录 DB 提交/回滚；不能用 Nginx 重发解释（当前为单上游且未配置代理重发）。

五类接案写入统一版本。检测启动不推进接案版本；取数时必须有与事实一致的输入 revision。同步/异步完成都做条件回写，过期不改 conflict_ready；同步两次写合并，关联事务含 cases 时不允许接案拒绝而 cases 已生效。

### 4.2 多轮与来源

保留 v0.3 的三种独立版本：业务 revision、临时 context_version、页面字段编辑序号。不得用一个内容散列代替三者。

- 只有服务端接收的真实原话/更正/选择可以构成来源。
- 结果交付和保存接受点均重新检查上下文与权限。
- 保存接受点复制不可变来源包并冻结上下文；不在模型或 PG 等待期间持有上下文互斥锁。
- 接受任一新输入/补充/口径/再生成即撤销全部旧候选自动来源资格；不依赖模型依赖声明，不允许新旧轮混选。新候选可以引用前轮原话。保存已接受则拒绝后来口径进入同次提交，已应用表单字不自动改。
- 人工改字后来源逐句支持不再自动成立；用户明确选择背景关联或未关联。旧草稿纳入新输入时保留原 revision、source_kind、origin_coverage，不能把人工未关联内容升级成原件事实；不递归建证据链。
- 历史快照与当前适用索引分开；A→B→A 不恢复旧来源资格。
- 暂存上下文失效不能让已保存来源失效；模型开关关闭也不关闭经授权的历史来源读取。

### 4.3 登录会话：采用当前 access 会话绑定

当前已有 auth_token_sessions 和自定义 UUID，可复用，暂不建设跨刷新会话族。

建议可信绑定为：账号 ID + 已验证的 access UUID + 对应数据库会话行 + 有效期，再绑定客户/接案。不接受前端自报 session_id；核验账号仍有效、试点白名单及当前角色/对象权限。

刷新得到新 access UUID、重新登录或换设备，均不自动接续旧临时上下文。旧 token 若服务端仍有效，其绑定的旧上下文按原有有效期/撤销规则处理；不能声称刷新已自动撤销所有旧 access token。登出或撤销哪个有效会话，必须由服务端状态决定，清空浏览器不等于服务端撤销。

服务端返回 expires_at = min(绑定 access/会话期限，创建+2 小时，最近已接受动作+30 分钟)。默认 3600 秒是 token 签发时长，不是本次整理可用时长；若签发 50 分钟后开始，最多约剩 10 分钟。只读轮询不续期，不足 45 秒不接新模型轮。

临时期限在来源包接受点检查；包复制后 TTL 清理不破坏它，但最终业务授权前 access 过期/撤销仍拒绝。最终检查后提交不受内存清理反向影响。已保存结果/墓碑可由重新登录的同一账号按当前权查询；临时聊天不搬运。

敏感试点路径不接受“没有会话行但签名有效”的兼容令牌。全局 access 类型限制属于小范围共用入口修正，需回归现有登录与调用方。Redis 失败、数据库不可用、用户/设备撤销均应有明确拒绝和回归；不扩成全所认证重建或刷新体系重做。

### 4.4 材料后置与已查调用方

本轮补查 cmd/qa-fixture、frontend/e2e、页面与对应 handler 测试：未发现发送用户修改材料数组的路径。前端 buildIntakePayload 使用固定 defaultMaterials，文件管理禁用；qa-fixture 未见接案材料构造，e2e 主要计 POST/PUT 请求及固定响应，不是材料编辑证据。

因此首版取消后端 material_changes CRUD，不新增材料控件。POST 保留原生合法初始化；PUT 不发送材料，服务端对 materials/material_changes（含空/null）或清单含 materials 明确整笔拒绝。既有材料 ID/状态/引用及 >20 记录完整保全仍必须通过。主体人工编辑正向回归继续保留。

已查范围不能证明外部调用方不存在。G00 确认脚本/集成真实调用；若存在实际材料编辑能力，停止该后置假设、定兼容方案并重估，不能静默忽略或留无保护旁路。

### 4.5 当前卡点与草稿恢复

当前卡点仅根据当前接案、明确角色/指派字段和现有合法动作计算。草稿创建人、metadata.lawyer_id、实际当前处理人并非天然同一人；没有可靠依据就显示“待分配/待核实”，不能从标题推断。

建议复用 /case 案件中心容器，新增经授权的接案草稿列表及 /case/create?intake_id=... 恢复入口，由服务端 GET 恢复真实对象、revision、子项 ID 和来源状态。现有读取最多返回 20 条主体/材料：必须提供完整分页/明确覆盖标志，不能将截断集合当全部后再保存。

1. 只应用摘要后保存，原主体真实 ID/受保护身份引用、关系、材料、负责人和未知 metadata 均保持；人工显式编辑子项时又能正确改变。

5. 当前客户撤权后，稀疏 PUT、旧保存结果回查、来源读取、上下文访问均拒绝。
6. 更正先到/保存先到两个执行顺序，数据库文字和来源均对应同一已接受口径。
7. 手工 A→B→A 后旧来源不复活；相同文字不能取代确认记录。
8. 新浏览器或清空本地内容后，从菜单恢复同一服务端草稿；超过 20 个子项不能被截断后删除。
9. 用虚构哨兵覆盖慢 SQL、SQL 失败、模型异常、请求/代理/浏览器存储；业务内容不得进入诊断日志。
10. 关闭模型后仍能正常人工保存、读取既有来源；失效的未保存聊天不伪装恢复成功。
