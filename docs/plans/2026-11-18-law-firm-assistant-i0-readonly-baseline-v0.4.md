# Law OA 窄版接案助手 I0 试用环境核验与估算

2026-11-18，Asia/Shanghai。配套为 [NP v0.4 设计](2026-11-18-law-firm-assistant-narrow-pilot-design-v0.4.md)与[验收矩阵](2026-11-18-law-firm-assistant-narrow-pilot-acceptance-v0.4.md)。[v0.3 I0](2026-11-16-law-firm-assistant-i0-readonly-baseline-v0.3.md)记录 11 月 16 日对本地工作树的观察和旧估算。

## 1. 本轮结论

试用环境的后端是 10 月 final5 交付包的 arm64 制品，PG 为 16.14，点验时一个后端和一个 PG 实例在运行。代理因绑定旧局域网地址而退出，后端回环就绪接口仍可访问。浏览器路径待原入口恢复后验证。

窄版继续使用单对象、单模板、标题与摘要、原生保存。已有草稿恢复、版本令牌和同步利冲事务可复用。现场 PG 缺少旧创建幂等分支依赖的列，接案原键回执与来源快照仍需新增。基础估算 **50–80 人日**，含 20% 缓冲 **60–96 人日**。适用前提见 §5。

### 2.1 与实现直接相关的实际结构

| 对象 | 现有结构或缺口 | 对本版的影响 |
|---|---|---|
| case_intakes | UUID 主键，client_id 为 bigint，title/description、status、metadata JSONB 等存在，intake_code 有唯一索引。无独立 revision、idempotency_key 或来源列，无旧幂等键唯一索引 | 冻结源码的接案版本读写使用 metadata 内的服务端令牌，不能从独立列缺失推断无并发保护。创建幂等分支对旧列存在性有条件判断，现场不能依赖它去重 |
| case_intake_parties | bigint 主键、UUID intake_id、其索引和受保护身份引用列存在 | 复用原生身份处理，补稳定 ID 与显式增量协议、关系和身份保全验收 |
| case_materials / material_files | 现有账本与附件版本表，包含 intake_id、状态/文件引用和 material_id | 沿用有权限的人工材料路径，助手保存不触达。验收覆盖账本、附件引用和文件版本 |
| auth_token_sessions | access/refresh UUID、到期和撤销时间存在，两个 UUID 都有唯一索引 | 复用会话身份与失效字段，实际期限、撤权和日志回归仍需执行 |
| client_creation_requests / approval_snapshots | 现场存在 | 参考客户创建去重的独立请求记录。审批快照现有唯一索引按审批请求、类型和来源版本约束提交历史。该索引的作用域和时点与原生接案保存回执不同，助手来源单独留存 |
| case_intake_write_requests / case_intake_source_snapshots | 本方案两个拟议表名现场均无 | 按窄版新增回执和来源快照。回执唯一性、迁移及失败回滚要在隔离 PG 验证 |
| 迁移历史 | 未发现 public.schema_migrations、migrations 或 golang_migrate，历史交付用 bootstrap 和固定追加 SQL。相关结构存在，包含 case_task_changes | 上述元数据可作结构基线。具体迁移账本和部署管理方式仍需核对，避免按迁移编号推断实库或重复迁移 |

只读取证复核保留了两个有边界的失败。无提权的 Docker 查询被拒绝，空输出不能计作零实例。主审首轮 PG 查询的约束类型连接缺少显式文本转换，随后修正类型并完整重查，未变更数据库。PG 子代理曾在服务器临时目录写入三个核验脚本，执行后删除。主审通过标准输入重新采证，并独立确认三个临时文件均已清理。入口故障本轮留给单独运维处理。
