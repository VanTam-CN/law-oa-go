# 试用前的旧标签处理

1. 在旧版本停止新编辑和新保存，保持旧标签打开。记录当前账号、对应草稿和待核实的保存请求。以同一账号回查原请求，未知结果只能继续回查或由用户明确放弃。退出浏览器会丢失仅内存的文字。
2. 由有权律师逐页检查未发送的文字、仅本页的预填以及本机草稿。需要保留的内容经原生入口核对后保存，再从原菜单重开核对。若旧页不能安全保存、请求未核实或归属不明，保留该页面与浏览器配置，终端继续 HOLD。
3. 律师明确放弃或已重开确认后，关闭所有旧写入标签。由获授权人员定向处理已确认归属的旧正文键。旧 v1 键缺少账号信息，不能自动归属；其他账号的 v2、未知归属以及未决保存标识分别保留。记录处置类别、操作者与时间，避免记录正文。
4. 试用使用核对过的新浏览器配置。已有 Service Worker 或无法检查的配置按页面提示暂停。切换之后再按原账号重开服务端草稿，核对编号、版本与来源。真实终端的处置由试用前演练另行取证。

C09 用两个同源合成页面演练明确放弃分支，其中旧页面没有后台写入者。新页无法读取旧页的 sessionStorage。脚本仅在隔离夹具中模拟人工定向处置，不代表真实终端已经处理。C08 单独验证真实保存结果未知后，切换账号再回查的路径。
