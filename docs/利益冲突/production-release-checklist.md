# 真实客户案件生产放行清单

本清单用于将当前 MVP 交接给律所运维、管理合伙人、合规负责人和冲突核查人。它不是法律意见，也不能替代 PD-01 至 PD-07 的书面决策。除非每个阻断项均有可复核证据，系统不得用于处理真实客户案件。

## 放行责任

| 角色 | 负责内容 | 不可替代的证据 |
| --- | --- | --- |
| 律所管理合伙人 | PD-01 至 PD-07、政策材料包管理职责签署、核查人任命 | 已签字决策物、系统签署记录、任命记录 |
| 合规负责人 | 政策材料包合规职责签署、质量规则、异常处置确认 | 独立账号签署记录、质量与处置凭证 |
| 冲突核查人 | 四类档案盘点、索引回填、范围与质量证据登记 | 四个 `run_id`、数量、哈希、来源版本和凭证引用 |
| 运维负责人 | 备份、密钥、PostgreSQL bootstrap、部署与健康检查 | 部署记录、备份恢复演练、健康检查响应 |

## 阻断式放行顺序

| 门禁 | 执行者 | 操作与证据 | 通过判据 |
| --- | --- | --- | --- |
| G0：决策冻结 | 管理合伙人、合规负责人 | 完成 `conflict-p0-law-firm-trial-spec.md` 的 PD-01 至 PD-07；保存版本、批准人和生效日期 | 所有决策物已签署，未决项没有被默认放行 |
| G1：生产基础设施 | 运维负责人 | 配置 PostgreSQL 15+、备份策略、真实 CORS、独立 `JWT_SECRET`、`APP_SECRET`、32 字节 `SUBJECT_DATA_KEY`、OnlyOffice 密钥；使用 TLS 连接 | 密钥不在仓库或日志中，恢复演练通过 |
| G2：结构初始化 | 运维负责人 | 在备份副本或空库执行 `docker compose up -d --build`；保留 `migrate` bootstrap 成功日志 | PostgreSQL bootstrap 成功；不得在生产执行历史混合 SQL `up/down` |
| G3：敏感数据回填 | 运维负责人、合规负责人 | 先执行 `go run ./cmd/backfill-sensitive-identities`；经审批与备份后执行 `go run ./cmd/backfill-sensitive-identities --apply` | 复核结果为零；没有未加密的主体或客户身份原文 |
| G4：冲突档案索引 | 冲突核查人 | 先执行 `go run ./cmd/backfill-conflict-index`；经档案核对后执行 `go run ./cmd/backfill-conflict-index --apply --actor-id <用户ID> --evidence-reference <凭证引用>` | 案件、客户、主体、关系四类来源均有 `COMPLETED` 运行记录、零缺口、数量闭合和哈希/凭证 |
| G5：治理登记 | 管理合伙人、合规负责人、冲突核查人 | 在“冲突治理”提交不可修改政策材料包，并由两个不同职责账号确认；登记有效核查人、代理人和回避声明；绑定四类来源范围/质量证据 | 唯一当前有效政策；任命人、核查人、代理人相互独立；四类范围均为 `ACTIVE + COMPLETE` |
| G6：账号与隔离验收 | 运维负责人、律师 A/B、冲突核查人 | 停用 `@example.test` 与 `demo_*` 账号；用三个独立真实权限账号完成 AT-01 至 AT-12，重点记录 B 对 A 隔离案件的列表、搜索、直接 URL、导出和缓存反向访问 | 未授权访问均被拒绝且留审计；没有将真实客户数据写入测试环境 |
| G7：最终技术放行 | 运维负责人、合规负责人 | 采集 `GET /health/ready` 响应、版本号、部署时间、四个索引运行编号、政策版本和签署记录 | `ready: true`；`conflict_p0_readiness` 健康；所有前序证据可追溯 |
