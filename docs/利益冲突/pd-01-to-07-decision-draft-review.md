# PD-01 至 PD-07 决策草案审阅意见

- **审阅日期**：2026-07-15
- **审阅对象**：[pd-01-to-07-decision-draft.md](/Users/mac/Downloads/pd-01-to-07-decision-draft.md)
- **结论状态**：不得按当前文本签署或据此放行 P0；完成本意见的 P0 修订并由律所专项负责人确认后，方可进入签署流程。
- **审阅边界**：本文核验公开法规、标准状态和规则文本与草案的对应关系；不构成法律意见，也不能代替执业登记地的专项顾问确认。

## 1. 总结

草案的结构、七项分批顺序、历史资料缺口披露、隔离墙最小披露、数据加密和三角色演练前置要求是正确的。下列事实也已核验：

1. 《律师业务档案管理办法》规定长期档案为二十年至六十年、短期档案为五年至十五年，具体期限由立卷人提出、主任决定，期限自法律事务办结或终止后的下一年起算。
2. `GB/T 45574-2025` 是现行推荐性国家标准，发布于 2025-04-25、实施于 2025-11-01；它采用风险识别和汇聚评估，不应被当作降低证件信息保护要求的理由。
3. 上海市律师协会的现行试行规则区分绝对禁止与相对禁止，并规定相对禁止情形的书面豁免要素；这只能作为上海或采用同等规则律所的政策参考，不是全国统一可执行配置。

但是，PD-02、PD-03、PD-07 存在会直接破坏 P0 安全边界的条款，必须先改；PD-05、PD-06、PD-04 和 PD-01 还需补足可执行条件。

## 2. 阻塞签署的 P0 修订

### RV-P0-01：有限例外不能由冲突核查人单人实质放行

- **位置**：草案第 81–88 行，尤其第 82、87 行。
- **问题**：文本要求核查人出具风险评估，而主任/管理合伙人仅保留否决权。实际效果是核查人可单人将 `COVERAGE_LIMITED` 案件从阻断转为可接案，与 P0 的职责分离原则矛盾。
- **必须改为**：核查人只能发起并建议有限例外；一名与案件无利害关系、具备书面授权的第二决策人必须明确批准才生效。无第二人、超时、续期材料不全或出现新命中时，状态均为阻断。高风险事项不得走例外路径。
- **验收**：直接调用例外批准 API 时，单人批准返回 `409 SECOND_APPROVAL_REQUIRED`；并发请求只产生一条待批准例外。

### RV-P0-02：无独立复核人时，客户同意不是通用替代路径

- **位置**：草案第 115–118 行。
- **问题**：第 118 行把“相关客户书面同意”与“拒绝接案”并列为外部独立意见不可得时的选项。这会使尚未完成绝对/相对禁止分类的事项，绕过独立复核直接进入豁免。
- **必须改为**：无独立复核人时，系统保持 `INDEPENDENT_REVIEW_UNAVAILABLE` 并阻断。只有外部独立复核完成、且根据执业登记地有效规则被分类为可豁免的相对禁止情形后，才可启动客户同意/豁免流程；绝对禁止情形不得以客户同意代替回避。
- **依据**：上海规则将绝对禁止与相对禁止分开处理；相对禁止须先告知并取得豁免，绝对禁止不得接受委托或实施委托行为。[上海市律师协会规则](https://www.lawyers.org.cn/info/12f43ae5268fb02fe0ecd36bb7033251)
- **验收**：无独立复核人的案件无法创建豁免；仅在已记录外部独立分类为 `RELATIVE_PROHIBITION` 后，豁免入口才可用。

### RV-P0-03：永久审计完整性证据不能等同于永久保留个人信息

- **位置**：草案第 240、248、251 行。
- **问题**：将 `compliance_audit_events` 整表永久保留且不物理删除，可能使其中可识别个人信息超出保存必要期限。个人信息保护法要求，除法律、行政法规另有规定外，保存期限应为实现目的所必要的最短时间。
- **必须改为**：
  1. 永久保留的只能是不可逆的完整性根、事件序号、时间戳、事件类型、保留策略版本和不可识别的关联摘要。
  2. 含姓名、证件掩码、案件标识、IP、访问理由或证据载荷的明细，按 PD-07 期限分层保存；到期后去标识化、密钥销毁或依政策删除，并将处置事件追加到完整性链。
  3. “不可物理删除”限定为保留期内的合规证据及完整性根，不得覆盖法定删除、去标识化或个人信息处置义务。
- **依据**：[个人信息保护法第十九条](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。
- **验收**：到期的明细无法通过业务接口读取；完整性链仍可证明历史处置发生且未被篡改。

## 3. 签署前必须补足的高优先级项

### RV-H-01：PD-05 需要“处理依据矩阵”，不能只写单独同意

- **位置**：草案第 171、176、181–184 行。
- **问题**：律师冲突库会处理客户、对方、关联方和历史主体的数据；并非每个主体都能实际取得同意。草案把“单独告知 + 单独同意”写成统一前置条件，但未为每种主体、用途、来源和处理依据建立可审计的规则。
- **必须新增的决策物**：字段处理依据矩阵。每一行至少包括数据主体类别、字段、目的、来源、处理依据、是否属于敏感个人信息的评估、告知方式、同意/单独同意要求、访问角色、保留期和行权处理方式。
- **工程约束**：没有匹配的、有效的处理依据记录时，系统不得收集全量证件号码；种子数据继续使用虚构值。带密钥摘要、掩码和审计日志仍是个人信息处理链的一部分，不能被当作不受规则约束的普通技术元数据。
- **依据**：个人信息处理需符合第十三条的处理依据；敏感个人信息还须满足特定目的、充分必要和严格保护，并按第二十九、三十条处理单独同意与告知。[个人信息保护法](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

### RV-H-02：PD-06 必须按执业登记地配置，不能把示例写成全国规则

- **位置**：草案第 202、207–218、272–280 行。
- **问题**：当前草案的“绝对禁止/相对禁止”“豁免函包含不追责”等表述与上海规则相符，但草案尚未确定执业登记地。广东“2025 年 9 月修订”未附发布机关、文号、有效文本链接，不能作为可审计的政策依据。
- **必须改为**：
  1. 新增 `jurisdiction_policy_profile`，在签署页写明执业登记地、适用规则名称、版本、发布机关、有效日期和核验链接。
  2. 在该配置生效前，系统只允许“待独立分类”，不允许自动判断可豁免或生成含“不追责”承诺的模板。
  3. “不追责”只在实际适用规则明确支持、且专项执业责任顾问确认模板后出现；它不得被设计为免除法定或未披露责任的通用条款。
- **依据**：上海规则第十二至十六条可作为示例，但其适用范围是上海会员。[上海市律师协会规则](https://www.lawyers.org.cn/info/12f43ae5268fb02fe0ecd36bb7033251)

### RV-H-03：豁免必须有机器可执行的复核期限

- **位置**：草案第 219–222 行。
- **问题**：“默认无固定到期日、每年台账复核”没有给出逾期后的自动状态。若年度复核未完成，系统仍可能持续放行。
- **必须改为**：每条豁免写入 `next_review_at`；到期未复核自动改为 `WAIVER_REVIEW_OVERDUE` 并阻断新增受控动作。是否设置最终到期日由本所政策决定，但年度复核不能只是一条人工提醒。

### RV-H-04：PD-01 的“唯一实时权威源”需有可测量的数据质量协议

- **位置**：草案第 44、48、53–58 行。
- **问题**：案管系统可作为当前主源，但“唯一实时权威源”不足以证明冲突索引已完整、及时且包含案件角色、别名和关系。
- **必须新增**：来源级 `source_of_truth`、同步方式、最大允许延迟、字段覆盖率、重复率、失败告警、人工更正流程和月度核对责任人。任何来源超过最大延迟或覆盖率下限时，正式检查自动标为 `COVERAGE_LIMITED`。

### RV-H-05：PD-04 只能门禁已接入的系统动作

- **位置**：草案第 137、141–153 行。
- **问题**：“出庭”或线下发函不能由当前系统直接阻断；写成系统 MUST 校验会形成无法证明的控制承诺。
- **必须改为**：系统门禁对象应为“生成、提交、用印申请、签章请求、导出或发送已接入系统的文书/请求”。线下出庭、个人邮箱、纸质文书须列为人工控制范围，并记录抽样比例、证据来源、责任人和违规升级时限。

## 5. 修订和签署顺序

1. 先修 RV-P0-01 至 RV-P0-03，并同步修改 P0 Spec 第 5、10 和 16 节的相应表述。
2. 完成 RV-H-01 的字段处理依据矩阵和 RV-H-02 的执业登记地政策配置；这两项完成前不得导入真实身份标识。
3. 明确 PD-01 的数据质量协议、PD-04 的已接入动作清单与 PD-06 的自动复核状态。
4. 由执业责任顾问核验 PD-06，由数据合规顾问核验 PD-05，由管理合伙人确认角色、例外和保留政策。
5. 签署后的政策版本、批准人、生效日期和适用范围必须写入系统配置并进入审计账本；不能只保存在 Markdown 文件中。

## 6. 本轮结论

草案可作为讨论底稿，但当前状态是“待修订后签署”，不是“可据此建真实数据或启动律所试用”。在 P0 修订完成前，仅可使用完全虚构、隔离的测试数据进行技术验证；不得向系统导入真实客户、真实案件或完整自然人身份标识。
