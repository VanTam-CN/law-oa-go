## 实现的闭环

已有本人草稿 → 当前权限读取 → Stub 多轮摘要候选与原句核对 → 人工选择应用摘要 → 共用原生按钮局部 PUT → 同事务摘要/来源/回执 → 新会话从原菜单重开核对来源。

新输入使旧候选失效，人工改动须重新对比；不会自动改标题、主体、材料或未知字段。改文后来源失效须重新核对或明确选择人工无来源保存。未决保存保留原键，只读回查或显式放弃，迟到请求不能复活。来源快照保留原句、轮次、账号及服务器时间，但不证明事实真实。

## 审核与修复记录

- GLM Flash 并行完成隔离环境准备、写路径初稿、摘要组件及两项行为测试；主代理审核并接管事务实现，完成集成、实际 PG/浏览器回归。
- 初稿发现并修正：旧协议保护不能以兼容 token 校验成功为前提；PG 布尔锁返回值；回执包重复包装；同文字新来源不能判 no_change；事务最终会话重验；原文不能 trim 后改写；未知 metadata 不能经 float64 整包重写。
- 浏览器发现原有登录延迟跳转会把刚打开的草稿拉回工作台，已改同步导航；通过真实登录回归及原登录用例验证。
- 最终复审另发现通用取值函数裁剪空格会破坏摘要 no_change 判定，改为逐字读取；结束/替换/成功保存上下文时停止到期计时器，避免旧正文被闭包保留。两项均补具体行为回归。
- 发现生成返回时会清空期间新输入，已改为只清本轮实际发出的文字，并用真实服务延迟请求回归。
- GLM Flash 独立只读复核最初怀疑旧全量绕过版本锁。主审补读 final5 原处理器并增加真实 PG 触发用例；原处理器本就强制版本和锁内比较。复核者正式撤回该 P1，限定范围内无未关闭 P0/P1。没有将模型意见直接当作验收。
