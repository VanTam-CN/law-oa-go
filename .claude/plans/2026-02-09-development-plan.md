## 一、执行摘要

### 核心变更：**隔离墙优先**

根据张律师的审核意见，将**隔离墙机制**开发提前到 Sprint 1 后半段，确保所有业务 API 在开发时都必须经过隔离墙中间件检查。

### 关键原则

> **"先砌墙，再放钱"** — 在任何业务逻辑运行之前，必须先建立好隔离墙机制。这不是可选项，而是系统的安全地基。

**中间件设计要求**:

```go
// 隔离墙中间件 - 必须在所有案件相关API之前执行
func EthicalWallMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        caseID := extractCaseID(c)

        // 1. 检查案件是否启用隔离墙
        if !isEthicalWallEnabled(caseID) {
            c.Next()
            return
        }

        // 2. 检查用户是否在白名单中
        userID := getCurrentUserID(c)
        if !isUserWhitelisted(caseID, userID) {
            // 3. 记录访问尝试
            logAccessAttempt(caseID, userID, c.ClientIP(), "denied")

            // 4. 返回403
            c.JSON(403, gin.H{"error": "该案件启用了隔离墙，您无权访问"})
            c.Abort()
            return
        }

        c.Next()
    }
}
```

**应用范围**: 所有案件相关的 API 必须应用此中间件

- `/api/v1/cases/*`
- `/api/v1/documents/*` (按案件筛选)
- `/api/v1/search*` (搜索结果过滤)

数据库 → 🔒隔离墙(P0!) → 待办/冲突/文档/财务 → 代管款/离职 → 测试

**变更说明**:

- 原路径: 数据库 → Inbox → ... → 风控 → 测试

| 检查项 | 验收标准 | 验证人 |

| 搜索过滤 | 搜索结果中不包含用户无权查看的隔离案件 | 张律师 |

**回退策略**: 如未通过，最多延期 1 个 Sprint。在延期期间，所有后续功能的案件 API 暂用硬编码保护。
